# motion-video

입력은 소개할 대상(URL·문서·설명)이다. 출력은 `videos/<id>/renders/video.mp4` 다.
기본값 · 1920×1080, 30fps, 한국어, 내레이션 있음(ElevenLabs 커넥터가 있을 때), 30~40초.

사람이 확인하는 지점은 2단계(레퍼런스 선택)와 3단계(스토리보드 승인) 두 곳이다.
그 밖의 단계는 묻지 않고 진행한다.

실행 기록 · 각 단계를 시작할 때 `node scripts/run-log.mjs videos/<id> stage <n>` 을 실행한다. 건너뛰는 단계(무음 영상의 4단계 등)는 끝에 `skip` 을 붙인다. 후보·선택·스토리보드 답·검수 촬영·렌더는 스크립트가 `videos/<id>/run-log.json` 에 스스로 남긴다.

## 0. 준비

먼저 `references/setup.md` 대로 필요한 도구(Node.js 24, Chrome, ffmpeg, Python 3, 프로젝트 의존성)를 확인한다. 없으면 묻지 않고 설치한다. 선택 도구(Python 패키지, yt-dlp, whisper, Codex CLI)는 그 기능을 쓰는 단계에서 같은 문서대로 확인한다.

```bash
[ -d node_modules/playwright-core ] || npm i
[ -f references/ref-index.json ] || node scripts/refs.mjs index
mkdir -p videos/<id>/{src,refs,renders,assets/{fonts,voice,bgm,sfx}}
cp templates/starter/assets/fonts/* videos/<id>/assets/fonts/
# three.js 로 만들기로 정한 경우에만 (3단계 승인 뒤)
cp vendor/three/three.min.js videos/<id>/assets/
# 유리·액체 금속·클레이·망점·홀로그램 재질이나 bloom 후처리를 쓰는 경우에만
cp vendor/three-looks/looks.js videos/<id>/assets/
```

- `<id>` 는 영어 소문자와 하이픈으로 짓는다. 이미 있는 폴더면 이어서 작업한다.
- 색인의 `built` 날짜가 30일보다 오래됐으면 `node scripts/refs.mjs index` 로 다시 만들고, 이어서 `node scripts/refs.mjs verify` 로 새 항목의 영상을 확인한다.
  이때 새로 생긴 항목은 톤 판정 없이 둔다. 판정이 없으면 검색·카탈로그에서 자동으로 빠진다. 판정과 사용자 리뷰는 제작이 끝난 뒤 따로 제안한다. 제작 중에 묻지 않는다.
- 소리 방식을 정한다. ElevenLabs 커넥터는 선택이다. `ToolSearch` 로 `Elevenlabs creative` 를 찾는다.
  - 도구가 있으면 · 소리 방식은 `ElevenLabs` 다. 4단계를 그대로 따른다.
  - 도구가 없고 사용자가 음원 파일을 줬으면 · 소리 방식은 `직접 음원` 이다. 파일을 `assets/voice`·`assets/bgm`·`assets/sfx` 에 넣는다. 내레이션 파일이 없으면 내레이션 없는 영상으로 만든다.
  - 도구도 파일도 없으면 · 소리 방식은 `합성` 이다. `scripts/synth.py` 로 음악·효과음을 코드로 만든다. 내레이션은 넣지 않고 화면 문구로 전달한다. 내레이션은 ElevenLabs 로만 만든다. 따로 묻지 않는다. 사용자는 3단계 스토리보드에서 이 방식을 확인한다.
  - 사용자가 소리 없는 영상을 요청하면 · 소리 방식은 `무음` 이다.
  - 정한 방식을 스토리보드 `## 방향` 의 형식 줄에 적는다(예 · `형식 · 1920×1080, 30fps, 약 30초, 소리 합성(음악·효과음, 내레이션 없음)`).

## 1. 사실 확인 → `FACTS.md`

1. 대상 페이지를 `curl` 로 받아 원문에서 숫자·조건·이름을 뽑는다. WebFetch 요약은 위치를 찾는 데만 쓴다.
2. `FACTS.md` 에 항목마다 값, 조건(한도·대상·기간), 출처 URL 을 적는다.
3. 원문에 값이 없는 항목은 "확인 못 함"으로 적고 영상에 넣지 않는다.
   대상 홈페이지의 바탕색·주색·주된 무늬도 출처와 함께 적는다. 2단계에서 톤을 고르는 근거다.
4. 제품 이미지·로고는 사용자가 허락한 경우에만 내려받는다. 해상도를 `file` 로 확인해 적는다.
5. 레퍼런스를 보기 전에 대상만 보고 `IDEA.md` 를 쓴다. 2단계의 `search`·`show` 보다 먼저 쓴다.
   맨 위에 "이 영상의 생각" 한 줄(대상을 어떤 그림 하나로 보여 줄지)을 쓰고, 그 아래 `| 시작(초) | 끝(초) | 보여 줄 것(이 대상의 사물·동작·변화) | 문구 |` 표를 쓴다. 문구는 `FACTS.md` 에서 확인한 것만 쓴다. 색·질감·움직임 방식은 적지 않는다. 3단계에서 레퍼런스로 정한다.
   레퍼런스를 먼저 읽고 장면을 짜면 레퍼런스의 사물·사건을 대상의 사물로 하나씩 바꿔 옮기게 된다. 아이디어를 먼저 정하면 닮음은 거의 그대로이고 전달력·소재 독립·기획이 오른다(`videos/exp-ref5` 3차 · 전달력 4.00 → 4.72, 소재 독립 3.11 → 3.83, 닮음 4.40 → 4.26).

## 2. 레퍼런스 후보 6개 → 사용자가 선택 (확인 지점 1)

0. `references/tone-catalog.md` 를 읽고, 대상에 맞는 톤 3~4개를 정한다. 톤마다 `node scripts/refs.mjs search --tone <톤id> [단어...]` 로 후보를 찾는다. 톤 id 는 `node scripts/refs.mjs tones` 출력의 첫 칸에 있다. 톤별 레퍼런스 수는 `tone-catalog.md` 의 `### 톤별 레퍼런스 수` 에 있다.
1. `node scripts/refs.mjs search <단어...> [--tag t]` 로 후보를 찾는다. 글자 수(`--min-chars`)로 구체성을 거르지 않는다. `lo:`·`ms:` 는 스타일 명세라 글이 길어서, 2000자로 거르면 남는 124편 가운데 74편이 그 두 출처이고 30편이 분석 노트다.
   단어를 바꿔 3회 이상 찾는다. 주제 단어(업종·제품 종류)와 형식 단어(kinetic, launch, explainer)를 섞는다.
2. 가까운 항목 8개 이상을 `node scripts/refs.mjs show <id>` 로 전문을 읽는다. 발췌만 보고 고르지 않는다. `lo:` 는 STYLE.md 의 핵심 절과 DEMO.md 의 숏 표만 나온다. DEMO.md 전체는 사용자가 고른 뒤에 읽는다(8번).
3. 서로 방향이 다른 6개를 고른다. 같은 유형을 2개 넘게 내지 않는다. 톤이 3개 이상 섞이게 고른다.
   어두운 발광 계열(정의는 `tone-catalog.md` 의 `## 톤을 고를 때`)은 6개 중 2개까지 낸다.
   여덟 출처(`pm:` prompt-motion, `gh:` awesome-opus5-5-videos, `cv:` claudevideo.org, `lo:` lemo-opuscar 스타일 라이브러리, `ms:` mg-styles-15 쇼케이스, `c2:` claude-video-2 스타일 명세, `pn:` Pinterest 의 손제작 영상, `fa:` AI Style Atlas 의 스타일 영상)를 같은 기준으로 본다. `c2:` 의 `show` 는 STYLE.md(색 hex·글꼴·이징 수치·움직임 규칙·금지 목록)를 낸다. `pn:`·`fa:` 는 프롬프트가 없다. `show` 는 영상 프레임을 보고 쓴 분석 노트를 낸다. `pm:`·`gh:`·`cv:` 가운데 작성자의 프롬프트에 화면 지시가 없는 항목에도 분석 노트가 있다(`search` 결과에 `(분석 노트)` 로 나온다). `show` 는 노트를 먼저 내고 작성자의 프롬프트를 뒤에 붙인다. 가져올 것은 노트의 "가져올 것"·"함정" 절에서 고른다. 출처를 이유로 순위를 올리거나 내리지 않는다. 기준은 주제와의 거리와 프롬프트의 구체성이다.
   아홉 번째 출처 `am:`(aimotion 표현 기법 데모)은 스타일 레퍼런스가 아니다. 후보 6개에 넣지 않는다. `search` 도 `--tech` 를 줄 때만 낸다. 3단계와 5단계에서 쓴다(`references/technique-refs.md`).
   `search` 의 톤 줄에 붙는 표시를 지킨다. 정의는 `tone-catalog.md` 의 표시(`flags`) 줄에 있다. `[실자료]` 항목(화면에는 "실자료 필요"로 나온다)도 후보로 낼 수 있다. 후보로 내면 `risk` 를 "실자료 필요 ·"로 시작하고 필요한 실제 자료의 종류를 적는다. 사용자가 그 후보를 고르면 8번에서 자료를 요청한다. `[AI이미지]` 항목(화면에는 "AI 이미지 필요"로 나온다)도 후보로 낼 수 있다. 사용자가 고르면 3단계에서 일러스트를 AI 이미지로 그린다(`references/ai-image.md`). `[실존]` 항목은 그 대상의 모습·이름·로고를 그리지 않는다(고정 규칙). `[새 항목 · 리뷰 전]` 을 후보로 낼 때는 `risk` 에 "사용자 리뷰 전 항목"을 적는다.
   조회수가 적힌 항목(claudevideo.org 의 모션그래픽)은 거리와 구체성이 비슷하면 조회수가 많은 것을 먼저 추천한다. `search` 도 같은 점수 안에서는 조회수 순으로 낸다.
   검색 결과가 한 출처로만 채워지면 단어를 바꿔 다른 출처의 항목도 읽은 뒤에 고른다.
4. `videos/<id>/refs/candidates.json` 을 쓴다. 항목마다 아래를 채운다. 문장은 사용자가 읽는 한국어로 쓴다.

   ```json
   [{ "id": "pm:<slug>, gh:<slug>, cv:<slug>, lo:<slug>, ms:<slug>, c2:<id>, pn:<slug> 또는 fa:<slug>", "label": "카드 제목", "tone": "tone-catalog.md 의 톤 이름", "what": "어떤 영상인가 (1~2문장)", "borrow": ["가져올 것"], "why": "이 영상에 맞는 이유", "risk": "주의할 점", "recommend": true }]
   ```

   `gh:` 항목은 원본에 제목이 없다. `cv:` 항목의 원본 제목은 사이트가 붙인 영어 설명이다. `lo:`·`ms:`·`c2:`·`fa:` 의 원본 제목은 영어 스타일 이름이다. 전문을 읽고 `label` 에 영상 내용을 나타내는 짧은 제목을 직접 적는다. `pm:` 항목은 `label` 을 비우면 원본 제목이 나온다.
   `what` 에 길이와 형식을 적는다. `lo:` 는 30~164초 이야기 영상이다(태그의 초). `ms:` 는 10초 쇼케이스이고 내레이션이 없다. `c2:` 는 10~18초 스타일 시연이다. `pn:` 은 사람이 만든 12~89초 영상이다(태그의 초). 코드로 만든 영상이 아니다. `fa:` 는 15초 스타일 영상이다.
   `recommend` 는 내가 추천하는 1개에만 넣는다. 카드에 "추천" 표시가 붙는다.
   제안 2~4개를 `videos/<id>/refs/suggestions.json` 에 쓴다. 항목은 `{"pick": "A", "text": "한 문장", "why": "생각할 거리 한 줄", "support": "<보조 id · 선택>"}` 다. 비교 화면의 메모 칸 위에 번호 목록으로 나온다. 사용자가 놓칠 만한 방향을 제안한다(두 후보 섞기, 한 후보를 줄이거나 바꾸기, 대상의 사실을 살리는 장면 등). 섞기는 선택이다. 섞을 때는 `support` 를 달고, 그 항목도 `show` 로 전문을 읽는다. 주 레퍼런스와 같은 재질·선 굵기로 다시 그릴 수 있는 요소만 섞는다(평면 UI 위 막대 인간처럼 재질이 다르면 통일감이 떨어졌다 · `videos/exp-h2-combo`). 위험이 있으면 `why` 에 적는다.
   어두운 발광 계열에 `recommend` 를 줄 때는 `why` 에 근거를 적는다. 근거는 `FACTS.md` 나 대상 홈페이지에서 확인한 어두운 바탕·발광이다. 근거가 없으면 이 계열을 추천하지 않는다. 이 계열 후보의 `risk` 는 "기본값 주의 ·"로 시작한다.
   `tone` 은 그 레퍼런스를 따라가면 영상이 입게 될 톤이다. 카드에 톤 표시가 붙는다.

5. `node scripts/refs.mjs board videos/<id>` 를 **백그라운드로** 실행한다 (Bash `run_in_background`). 비교 화면이 브라우저에 열린다.
   `pm:`·`cv:`·`lo:`·`ms:`·`c2:`·`pn:`·`fa:` 항목과 영상 파일이 있는 `gh:` 항목은 카드에서 영상이 재생된다. X 게시물에서 온 `gh:` 항목은 영상을 내려받을 수 없어서 영상 대신 "X 원본에서 영상 보기" 링크가 나온다.
   카드마다 영상(또는 X 링크), 제목, 가져올 것, 이유, 프롬프트 앞부분, 고르는 단추가 나온다. `label` 을 비우면 원본 제목이 나온다.
6. 채팅에도 같은 내용을 표로 적는다. 표의 열은 `기호(A~F) · 제목 · 톤 · 어떤 영상인가 · 가져올 것 · 원본 링크` 다. id 만 적지 않는다. `[실자료]` 후보는 제목 뒤에 "(실자료 필요)"를, `[AI이미지]` 후보는 "(AI 이미지 필요)"를 붙인다.
   내 추천 1개와 이유를 한 줄로 붙이고, 제안이 있으면 그 아래에 번호 목록으로 적는다. "화면에서 단추로 고르세요"라고 알린 뒤 턴을 끝낸다.
7. 사용자가 단추를 누르면 명령이 끝나고 `refs/choice.json` 이 생긴다 (`pick`, `id`, `memo`). 이 파일을 읽는다.
   사용자가 메모 칸 아래의 "적은 내용만 보내기"를 누르면 `pick` 과 `id` 가 `null` 이고 `memo` 만 온다. 그때는 `memo` 의 글에서 선택과 요청을 읽는다.
   제안이 있었으면 `suggestion` 과 `suggestionIndex`(1부터)가 함께 온다. `accepted` 는 그 제안대로(`support` 가 있으면 함께 온다), `edited` 는 제안을 고친 `memo` 대로, `ignored` 는 고른 카드대로 만든다. 보조 요소가 있으면 8번에서 `## 레퍼런스` 의 보조 줄에 적는다.
   사용자가 화면 대신 채팅으로 답하면 그 답을 쓴다. 답을 받기 전에는 3단계로 가지 않는다.
   `AskUserQuestion` 은 선택지가 4개까지라 여기서 쓰지 않는다.
8. 고른 항목이 `lo:` 면 `show lo:<slug> --demo` 로 DEMO.md 전체(숏 표·음악 구조)를 읽는다. 숏 표에서는 박자·카메라·전환을 읽는다. 숏의 사물·사건은 장면으로 옮기지 않는다. 고른 항목을 `STORYBOARD.md` 의 `## 레퍼런스` 에 적는다. `memo` 와 나머지 후보에서 보조로 가져올 것이 있으면 함께 적는다.
   고른 항목에 `실자료` 표시가 있으면 사용자에게 실제 자료를 요청한다. 순서는 `.claude/skills/motion-catalog/SKILL.md` 2단계 3번의 `실자료` 줄과 같다. 사용자가 이미 준 자료가 있으면 모자란 것만 요청한다. 답을 받기 전에는 3단계로 가지 않는다.
   고른 항목에 `AI이미지` 표시가 있으면 3단계에서 `references/ai-image.md` 를 따른다. 사용자에게 따로 묻지 않는다.

원격 채널(Telegram·Slack)처럼 브라우저를 볼 수 없는 환경이면 5번을 `--no-open` 으로 실행하고, 6번의 표에 원본 링크를 반드시 넣어 채팅으로 답을 받는다.

## 3. 스토리보드 → 사용자 승인 (확인 지점 2)

`references/storyboard-template.md` 의 형식으로 `videos/<id>/STORYBOARD.md` 를 쓴다. 쓰기 전에 `references/motion-rules.md` 와 `references/tone-catalog.md` 를 읽는다.

- 장면의 내용(무엇이 나오는가)은 1단계의 `IDEA.md` 에서 가져온다. 레퍼런스에서는 보여 주는 방식(색·질감·구도·타이포·움직임·전환·박자·화면 밀도)을 가져온다. 시각을 옮기거나 장면을 합치고 나누는 것은 된다. 레퍼런스의 사물·사건·장면으로 새 장면을 더하거나 `IDEA.md` 의 사물을 레퍼런스의 사물로 바꾸지 않는다. `IDEA.md` 에서 바꾼 것은 `## 방향` 의 "아이디어에서 바꾼 것" 줄에 적는다(없으면 "없음").
- `## 방향` 에 톤(옷)·이야기 방식·움직임 원칙 세 줄을 쓴다. 선택한 레퍼런스의 톤을 따르되, 대상에 맞지 않으면 이유를 적고 바꾼다.
- `## 방향` 에 "쓰지 않는 것" 한 줄을 쓴다. `tone-catalog.md` 표의 그 톤 칸과 표 위의 공통 문장에, 이 영상에서 더 뺄 것을 더한다.
- 장면표의 전환 칸은 `motion-rules.md` 의 `## 전환 레시피` 처럼 "앞 사물 → 건너가는 동작 → 뒤 사물"로 적는다.
- 표현 기법(`am:`)은 에이전트가 찾는다. 사용자에게 기법을 고르게 하거나 묻지 않는다.
  톤이 정해지면 `node scripts/refs.mjs search --tech --tone <톤id>` 를 실행한다. 장면에 필요한 효과는 단어로 한 번 더 찾는다(`search --tech <단어>`).
  장면에 맞는 기법이 있으면 `references/technique-refs.md` 를 읽고 `show am:<id>` 로 구현 노트를 읽은 뒤 `## 레퍼런스` 의 `기법` 줄에 적는다. 맞는 기법이 없으면 쓰지 않는다. 기법에서는 효과를 만드는 방법만 가져온다.

- 내레이션 원문을 문장 단위로 적는다. 화면 문구를 그대로 읽지 않는다. 숫자는 읽는 소리(한글)로 따로 적는다.
- 장면표에는 장면마다 예상 시간, 역할, 화면 문구 원문, 조건 표기, 모션, 다음 장면으로의 전환을 적는다.
- 음악 흐름(장르, BPM, 도입·고조·정점·종결 시각)을 적는다. 기본 흐름은 잔잔한 도입에서 정점까지 계속 커지는 구조다.
- 과장이 되는 표현을 쓰지 않는다. 한도가 있는 혜택을 "절반이 돌아온다"처럼 말하지 않는다.

- 사진을 쓰는 장면은 장면표의 "화면" 칸에 `assets/` 안의 파일 이름(확장자 제외)을 적는다. 확인 화면이 그 사진을 장면 카드에 넣는다.
- 고른 레퍼런스에 `AI이미지` 표시가 있거나 일러스트 장면을 AI 이미지로 그리기로 하면 `references/ai-image.md` 를 읽는다. `## 방향` 에 "AI 이미지" 줄을 쓰고, 디자인 시트와 장면 키프레임을 승인 전에 만들어 장면표 "화면" 칸에 파일 이름을 적는다.

승인은 확인 화면에서 받는다. 장면 카드에는 글 대신 뼈대 화면의 키프레임을 넣는다(사용자 결정 2026-11-24).

0. 뼈대 `src/index.html` 을 만든다. 장면마다 가운데 시각의 한 장면이 최종 화면과 비슷하면 된다(배치·글자 크기·색·주요 도형·화면 문구). 움직임·전환·박자·질감·세부 장식은 만들지 않는다. 장면 사이는 컷으로 바뀌어도 된다. seek 계약(`seek-pattern.md` 의 계약·금지)은 지킨다. 로고·사진이 아직 없으면 회색 상자로 자리만 둔다.
   키네틱 타이포 38초 8장면 영상에서 약 1.5분이 걸렸고 최종 화면과 배치·글자·색이 거의 같았다(`videos/exp-h5-keyframe`). 일러스트·3D 장면은 더 걸린다. three.js 장면은 평면 그림으로 자리를 잡아도 된다.
   확인 화면을 띄우기 전에 `node scripts/lint-storyboard.mjs videos/<id>` 를 실행한다. 핵심 문구 길이, 금지 전환, `## 방향` 네 줄, 기법 줄의 데모 소재, 추천 1개, 어두운 발광 추천 근거, 마지막 정지를 검사한다. 위반이 나오면 STORYBOARD.md 나 candidates.json 을 고치고 다시 실행한다. 일부러 남기는 위반(예 · 6단어 슬로건)은 이유를 8단계 보고에 적는다.
1. `node scripts/storyboard.mjs videos/<id> --keyframes` 를 **백그라운드로** 실행한다. 장면마다 가운데 시각을 찍어 `keyframes/NN.png` 로 두고 `storyboard.html` 을 브라우저에 연다.
   장면마다 키프레임이 16:9 카드로 나오고, 장면·대사·음악·전체에 의견 칸이 있다. 뼈대가 없으면 글 카드로 나온다.
2. 채팅에는 대사 전문, 장면표, 음악 흐름, `## 방향` 의 톤·이야기 방식·움직임 원칙·쓰지 않는 것을 짧게 적고 "화면에서 의견을 적고 보내세요"라고 알린 뒤 턴을 끝낸다.
3. 사용자가 보내면 명령이 끝나고 `storyboard-feedback.json` 이 생긴다. `decision` 은 `approve` 또는 `revise`, `comments` 는 `[{target, text}]` 다.
   - `revise` · 의견대로 `STORYBOARD.md` 와 뼈대를 고치고 1번부터 다시 한다.
   - `approve` 인데 의견이 있으면 · 의견대로 고친 뒤 무엇을 고쳤는지 알리고 4단계로 간다.
   - `approve` 이고 의견이 없으면 · 상태 줄을 `승인 (날짜)` 로 바꾸고 4단계로 간다.
4. 사용자가 화면 대신 채팅으로 답하면 그 답을 쓴다. 승인 전에는 4단계로 가지 않는다.

원격 채널처럼 브라우저를 볼 수 없는 환경이면 `--no-open` 으로 파일만 만들고, 대사 전문·장면표·음악 흐름·`## 방향` 을 채팅에 모두 적어 채팅으로 승인을 받는다.

## 4. 소리 (ElevenLabs · 선택)

0단계에서 정한 소리 방식에 따라 나눈다.

- `무음` · 이 단계를 건너뛴다. `video.json` 의 `audio` 를 `{}` 로 둔다. `mix.py` 가 무음 트랙을 넣는다.
- `합성` · `references/audio-synth.md` 의 순서를 따른다. 아래 1·2번은 하지 않는다. 3·5번의 생성은 `synth.py` 로 대신한다. 4번의 측정은 하지 않는다(박을 스크립트가 정한다). 장면 전환은 `synth.py music` 이 출력한 마디 첫 박에 놓는다.
- `직접 음원` · 아래 1·3·5번의 생성은 하지 않는다. 2·4·6번의 측정과 시간표 작성은 그대로 한다. 내레이션은 `audio-probe.py` 로 문장 경계를 재고, 음악은 `--onsets --write` 로 박을 잰다.
- `ElevenLabs` · `references/audio-elevenlabs.md` 의 순서를 따른다. 요약:

1. `creative_create_flow` 로 flow 하나를 만들고 모든 호출에 그 `flow_id` 를 넘긴다.
2. 내레이션 생성 → 내려받기 → `audio-probe.py` 로 문장 경계를 잰다 → 문장 사이 간격을 넓혀 장면 시작 시각을 정한다.
3. 장면 시각이 정해진 뒤에 음악을 만든다. 프롬프트에 도입·고조·정점·종결의 초 단위 시각을 적는다.
4. `audio-probe.py` 로 음악의 고조 시작과 종결 화음 시각을 재고, `delay`·`cut`·`repeat` 로 정점 장면과 마지막 장면에만 맞춘다. 음악은 프롬프트의 시각을 자주 따르지 않는다. 다시 만들지 말고 이 값으로 맞춘다.
   그다음 `python3 scripts/audio-probe.py videos/<id>/assets/bgm/<파일> --onsets --write videos/<id>` 로 타격음 시각을 `video.json` 의 `beats` 와 `src/beats.js` 에 쓴다. `delay`·`cut`·`repeat` 을 바꾸면 다시 실행한다.
   음악을 고정한 뒤 나머지 장면 전환은 장면 쪽을 박으로 옮긴다. 전환마다 ±0.6초 안의 가장 가까운 마디 첫 박으로 옮기고, 내레이션 문장 경계는 넘지 않는다. 방법은 `audio-elevenlabs.md` §2 6번 끝에 있다(`videos/exp-h6-sync`). `직접 음원` 도 같다.
5. 효과음을 만든다. 3종 안팎이면 충분하다.
6. `video.json` 에 시간표를 적는다. 형식은 `templates/starter/video.audio-example.json` 을 따른다. 소리가 없으면 `"audio": {}` 로 둔다(`templates/starter/video.json`). 단 `sfx` 는 `audio-elevenlabs.md` §3 의 4칸 형식으로 적는다.

생성 호출은 재시도 목적으로 다시 부르지 않는다. 다시 부르면 크레딧이 한 번 더 나간다.

생성을 기다리는 동안에는 다음 단계의 문서 작업(음악 프롬프트, 효과음 목록, `index.html` 뼈대)을 먼저 한다. 그래도 기다려야 하면 Bash `run_in_background` 로 기다린다. 전경 `sleep` 은 막혀 있다.

## 5. 화면 → `src/index.html`

`references/seek-pattern.md` 를 읽고 `templates/starter/src/index.html` 을 본보기로 쓴다.
3단계의 뼈대 `src/index.html` 을 이어서 완성한다. 뼈대의 배치는 사용자가 키프레임으로 승인한 화면이다. 배치·색·문구를 크게 바꿔야 하면 바꾸기 전에 사용자에게 알린다.

- 모든 스타일 값은 `window.seek(t)` 안에서 t 만으로 계산한다. CSS transition, 타이머, 프레임 사이에 남는 상태를 쓰지 않는다.
- 장면의 시작 시각은 4단계에서 정한 시각(내레이션 문장 경계 안에서 박으로 옮긴 시각)을 쓴다. 숫자·문구는 대사의 해당 단어가 나오는 시각에 맞춘다. 단어 시각은 `audio-probe.py <내레이션> --words` 로 잰다.
- 글자는 프로젝트 안의 글꼴 파일만 쓴다. 한국어 기본 글꼴은 Pretendard 다. 영어 글꼴은 고른 레퍼런스에 맞춰 영상마다 고른다. 글자 크기는 `references/motion-rules.md` 의 글자 기준을 따른다.
- 스토리보드의 움직임 원칙(프로필)에 맞는 도우미를 `seek-pattern.md` 의 `### 톤별 프로필 도우미` 에서 가져온다.
- `src/beats.js` 가 있으면 `<script src="beats.js"></script>` 로 읽고, 정점 구간을 `### 박자 도우미` 로 맞춘다.
- three.js 로 만들면 `seek-pattern.md` 의 `## three.js` 를 따른다. 글자는 DOM 층으로 3D 위에 올린다.
  유리·액체 금속·클레이·망점·홀로그램 재질과 후처리는 `### three-looks 키트` 를 따른다. 본보기는 `vendor/three-looks/demo/src/index.html` 이다.
- 손그림·수묵·판화 톤을 canvas 로 그리면 `seek-pattern.md` 의 `## canvas 손그림` 을 따른다. 원테이크면 `### 월드 카메라`, 카툰 톤 캐릭터면 `### 카툰 연기 도우미` 를 쓴다.
- AI 이미지로 그린 그림은 `references/ai-image.md` 의 `## 화면에 올릴 때` 를 따른다.
- 스토리보드 `## 레퍼런스` 에 `기법` 줄이 있으면 `references/technique-refs.md` 의 `## 화면 코드로 옮길 때` 를 따른다. `show am:<id>` 로 구현 노트의 "기법과 원리"·"결정성 전략"을 다시 읽고 `seek(t)` 로 다시 쓴다. aimotion 의 파일을 불러오지 않는다.

   - 화면 문구와 조건 표기가 `STORYBOARD.md`·`FACTS.md` 와 같은지
   - 톤이 스토리보드의 톤과 같은지. 프로필 밖의 움직임(예 · `smooth` 톤에 등속 이동)이 섞이지 않았는지. 스토리보드의 "쓰지 않는 것"이 하나도 보이지 않는지
     "쓰지 않는 것" 가운데 움직임에 관한 항목(튀는 등장, 박자와 무관한 교체 등)은 그 구간의 연속 3~6프레임을 `--snap` 해서 본다. 이렇게 보지 못한 항목은 8단계 보고의 "확인하지 못한 것"에 적는다
   - 스토리보드에 `기법` 줄이 있으면 기법이 들어간 구간도 연속 3~6프레임을 `--snap` 해서 본다. 숫자·글자가 움직이는 구간을 먼저 본다. 기법 구간에서 글자 겹침·잘림·번짐이 새로 생겼다(`videos/exp-h3-tech`)
   - three.js 로 만들었으면 `page error` 출력이 없는지, 캔버스가 빈 화면이 아닌지
3. 결함을 고치고 해당 시각만 다시 찍는다. 결함이 없을 때까지 반복한다.
   회차마다 2번에서 찾은 결함 수를 `node scripts/run-log.mjs videos/<id> defects <수>` 로 남긴다. 결함이 없었으면 0 이다.
4. 결함이 없으면 1번의 시각들을 `--det` 를 붙여 한 번 더 찍는다. 새 페이지에서 같은 시각을 역순으로 다시 찍어 화소를 비교한다(스냅 시간이 약 2배).
   `결정성 · 다름` 이 나오면 seek 밖에 남는 상태, 첫 seek 에 기대는 코드, t 로 바꾸는 CSS·SVG 필터를 찾아 고친다. 필터가 `motion-rules.md` 레시피로 쓴 것이거나 기존 영상을 다시 렌더한 경우면 고치지 않고 보고에 적는다.
   `결정성 · 작은 차이` 가 나오면 그 시각의 차이 지도 `renders/snaps/det-t*.png` 를 Read 로 본다. 다른 화소가 빨갛게 칠해져 있다. 글자·도형 가장자리를 따라 난 가는 빨간 선은 그리기 오차라서 그대로 둔다. 글자나 도형 하나가 통째로 빨간 덩어리면 그 요소가 seek 밖 상태에 기대는 것이므로 고친다. 작은 요소의 어긋남은 화소 수가 기준 아래로 나오기 때문에 이렇게 눈으로 본다.

## 7. 렌더와 검증

```bash
node scripts/render.mjs videos/<id> && python3 scripts/mix.py videos/<id>
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height -of default=nw=1 videos/<id>/renders/video.mp4
python3 scripts/audio-probe.py videos/<id>/renders/video.mp4 --step 2
python3 .claude/skills/motionmaxxing/scripts/look.py videos/<id>/renders/video.mp4 --out videos/<id>/renders/look --expect <video.json 의 duration> --expect-audio --hold-warn 0
```

`look.py` 출력에서 판정과 보고에 쓰는 것은 넷이다(G0·끝 정지·통합 음량·true peak). 숫자는 8단계 보고의 검사 표에 옮긴다. `G2` 는 맨 아래 줄처럼 참고로만 본다.
- `G0` · 디코드, 빈 화면 아님, 길이, 소리. PASS 여야 한다
- `end hold` · 끝 정지 길이. 1초 이상이어야 한다(`motion-rules.md` `## 구성`). 상한은 두지 않는다
- `audio` 의 `integrated` LUFS 와 `true peak` · 음량 목표를 정하기 전이라 기준이 없다. 값만 기록한다. look.py 의 true peak·LUFS `FLAG` 도 판정에 쓰지 않는다
- `G2`(단색 프레임)는 참고로만 본다. 첫 0.5초의 단색 도입과 "점 → 화면 전체 배경"·"덮고 바꾸기" 전환은 의도한 단색이다

`G3`(끝 카드 1.4초·마지막 숏 25%), `MOTION`, `cut sync`, 앞뒤 무음 `FLAG` 는 판정에 쓰지 않는다. 우리 영상은 컷 대신 사물 전환으로 잇고, 내레이션은 1.0~1.2초에 시작하기 때문이다. `--hold-warn 0` 은 끝 정지 1.4초 상한 WARNING 과 그 줄의 자르기 명령을 끈다. 끝 정지 값은 그대로 나온다. Windows 에서는 시트에 타임코드가 빠진다(글꼴 경로가 macOS·Linux 뿐). ffmpeg 에 `drawtext` 필터가 없을 때(Homebrew 기본 ffmpeg 등)도 빠진다. 오류는 아니다. look.py 는 motionmaxxing 스킬의 파일이므로 고치기 전에 사용자에게 묻는다.

완료 조건 · 길이가 `video.json` 과 같다. 영상·음성 스트림이 둘 다 있다. `look.py` 의 `G0` 이 PASS 이고 끝 정지가 1초 이상이다(모자라면 `seek-pattern.md` 의 마지막 구간 정지 `Math.min(t, 끝-1.2)` 를 본다). `mix.py` 가 `경고 없음` 을 출력한다. 음량 곡선이 스토리보드의 음악 흐름과 같은 모양이다.
`renders/look/sheet.jpg` 를 Read 로 보고 최종 mp4 를 한 번 더 본다.

## 8. 보고

보고 전에 `node scripts/run-log.mjs videos/<id> check` 를 실행한다. 빈 곳이 나오면 채운다.

로컬이면 `open videos/<id>/renders/video.mp4` 로 연다. 원격 채널(Telegram·Slack)이면 열지 않고 mp4 파일을 채널로 보낸다. 그다음 아래를 적는다.

- 파일 경로, 길이, 장면 구성 표
- 검사 표 · 열은 `검사 · 값 · 기준 · 판정` 이다. 행은 결정성(6단계 `--det`), 글꼴 로드(`fonts · n개 loaded` 또는 `font not loaded`), `look.py` 의 G0·끝 정지·통합 음량·true peak, `mix.py` 경고, 목소리-음악 차이다. 값은 명령 출력에서 그대로 옮긴다. 통합 음량·true peak 의 기준 칸은 "정하지 않음", 판정 칸은 "기록만"이다. 내레이션이 없거나 `mix.py` 가 비교하지 못했으면 목소리-음악 차이 칸에 그렇게 적는다
- 확인한 것(숫자로)과 확인하지 못한 것을 나눈다. 청취는 확인하지 못한 것이다. 소리는 측정값으로만 확인했다고 적는다
- 스토리보드와 달라진 점 (없으면 "없음")
- 표현 기법(`am:`)을 썼으면 쓴 기법의 id, 가져온 기술, 가져오지 않은 것
- AI 이미지로 그렸으면 그린 그림 목록과 코드로 만든 것(`references/ai-image.md` 의 `## 보고`)
- `mix.py` 가 출력한 경고와 그 처리 (없으면 "경고 없음")
- 가장 약한 장면 1개와 고칠 방법
- 직접 들어 볼 시각(최대 5개) · 정점 시작과 종결 화음(STORYBOARD 의 음악 흐름과 `audio-probe.py` 측정값), 큰 전환 2곳(장면표), 효과음이 대사와 겹치는 곳(`video.json` 의 `sfx` 와 `voice.segments`. 4칸 sfx 는 시각 − 동기점이 소리 시작이다). 내레이션이 없는 영상은 마지막 항목을 뺀다. 효과음 배치에 대한 청취 의견도 이 시각들로 받는다
- 이번에 새로 겪은 함정 한 줄 제안. 사용자가 동의한 것만 `seek-pattern.md` 의 `## 겪은 함정` 에 넣는다. 답을 기다리며 멈추지 않는다
- 색인에 판정 전(검토 대기) 항목이나 `new: true` 항목이 있으면 판정·사후 리뷰를 한 줄로 제안한다(`tone-catalog.md` 의 `### 톤별 레퍼런스 수`). 답을 기다리며 멈추지 않는다
- 사용자가 다음에 할 일

## 수정 요청

렌더 뒤 수정 요청을 받으면 먼저 `node scripts/run-log.mjs videos/<id> revision "바꾼 것" --redo <다시 하는 첫 단계>` 를 실행한다. 요청이 여러 개면 하나씩 남긴다.

| 바꾸는 것 | 다시 하는 단계 | 크레딧 |
|---|---|---|
| 화면 배치·색·모션 | 5 → 6 → 7 | 없음 |
| 화면 문구·조건 표기 | 3(문서만 수정) → 5 → 6 → 7 | 없음 |
| 일러스트 그림(AI 이미지) | 그 그림만 다시 그림(`ai-image.md`) → 5 → 6 → 7 | 없음 (ChatGPT 요금제 한도를 쓴다) |
| 음량·효과음 위치·음악 맞춤 | `video.json` 수정 → `mix.py` → `look.py` | 없음 |
| 대사 | 3(승인) → 4 전체 → 5 의 시각 → 6 → 7 | 사용 |
| 음악 분위기 | 4 의 음악만 → 7 | 사용 |
