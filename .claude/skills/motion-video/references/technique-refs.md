# 표현 기법 레퍼런스 (`am:`)

3단계(스토리보드)와 5단계(화면)에서 읽는다.
기법은 에이전트가 찾아서 쓴다. 사용자는 기법을 지시하지 않는다. 사용자에게 기법을 고르게 하거나 묻지 않는다. 카탈로그 화면에도 나오지 않는다.

출처 · aimotion (https://kstost.github.io/cokacmotion/ · https://github.com/kstost/cokacmotion · MIT © 2026 kstost). 기법 하나에 데모 하나다. 166편, 분류 12개.
데모는 모두 세로 1080×1920, 8~10초다. t 의 순수 함수 `frame(t)` 로 그린다. 우리 `seek(t)` 와 같은 방식이다.

## 스타일 레퍼런스와 다른 점

| | 스타일 레퍼런스 (`pm:` `gh:` `cv:` `lo:` `ms:` `pn:`) | 표현 기법 (`am:`) |
|---|---|---|
| 가져오는 것 | 구조·박자·전환·타이포 처리 | 효과를 만드는 방법 (알고리즘·수식·셰이더 구조·굽는 방법·이징의 구조) |
| 가져오지 않는 것 | 문장·브랜드 이름 | 데모의 소재·장면·이야기·구도·카메라 동선·문구·색, 세로 9:16·8~10초 형식 |
| 영상 하나에 | 1개 | 0개 이상 |
| 카탈로그 화면 | 나온다 | 나오지 않는다 |
| 누가 고르나 | 사용자 (카탈로그나 후보 화면에서) | 에이전트. 쓴 기법은 스토리보드의 `기법` 줄과 8단계 보고에 적는다 |
| 2단계 후보 6개 | 낸다 | 내지 않는다 |
| `search` | 기본 | `--tech` 를 줄 때만 나온다 |
| 톤 판정의 뜻 | 그 영상의 톤 | 그 기법을 쓸 수 있는 톤(최대 2개). "해당 없음"은 톤과 무관한 연출 장치·형식이다 |
| 톤별 레퍼런스 수·상태 | 센다 | 세지 않는다 (`tones` 의 "기법" 칸에 따로 센다) |

- 장면은 영상의 대본에서 먼저 정한다. 그 표현에 맞는 기법을 그다음에 찾는다. 마음에 드는 데모에 대본을 맞추지 않는다.
- 데모를 본 사람이 영상에서 그 데모의 장면을 알아보면 다시 짠다.

## 찾기

3단계에서 톤이 정해지면 아래 순서로 찾는다.

1. `node scripts/refs.mjs search --tech --tone <톤id>` 를 실행한다. 그 톤에 쓸 수 있는 기법이 나온다.
2. 장면에 필요한 효과를 단어로 찾는다. `node scripts/refs.mjs search --tech <단어...>`. 기법 이름·배울 점·라이브러리·분류에서 찾는다.
3. 장면에 맞는 기법만 `node scripts/refs.mjs show am:<id>` 로 읽는다. 구현 노트(NOTES.md) 전문과 소스 파일 주소가 나온다. 번호만 적어도 된다(`show am:18`).
4. 맞는 기법이 없으면 쓰지 않는다. 기법을 쓰려고 장면을 바꾸지 않는다.

- 결과의 `톤:` 줄에 `[기법]` 이 붙는다.
- `node scripts/refs.mjs tones` 의 "기법" 칸은 톤마다 쓸 수 있는 기법 수다.

## 구현 노트 읽는 법

| 절 | 쓰임 |
|---|---|
| `## 화면` | 데모가 그린 것이다. 기법이 어디에 쓰였는지만 본다. 옮기지 않는다 |
| `## 기법과 원리` | 가져올 것이다. 항목마다 `main.js:줄` 을 가리킨다 |
| `## 결정성 전략` | `seek(t)` 로 옮길 때의 근거다. 굽는 것과 t 로 읽는 것이 나뉘어 있다 |
| `## 지표` | `frameMs` 가 프레임당 1초를 넘으면 해상도를 낮추거나 로드 때 굽는다 |
| `## 한계와 다음 단계` | 조정할 값과 알려진 한계다 |

- 노트가 가리키는 줄은 `show` 끝의 `## 소스` 주소에서 받아 읽는다. 예 · `curl -s <main.js 주소> | sed -n '170,230p'`. 원리를 설명할 수 있을 때까지 읽는다.
- 1초마다 한 장씩 찍은 그림(sheet)이 있는 데모는 `## 소스` 의 마지막 줄에 그 주소가 나온다.

## 스토리보드에 적는 법 (3단계)

`## 레퍼런스` 에 기법마다 한 줄을 적는다.

```
- 기법 · am:18-watercolor — 물 층과 안료 층을 로드 때 고정 dt 로 굽고, seek 는 구운 단계 중 t 에 맞는 장을 놓는다 (장면 2 배경)
```

- 문장에는 기술만 적는다. 데모의 소재(산·고래·편지 등)를 넣지 않는다.
- 장면표의 "모션" 칸에는 화면에 보이는 결과를 말로 적는다. 기법 이름이나 id 를 적지 않는다. 사용자는 기법을 모른다.
- 기법이 그 톤의 "쓰지 않는 것"이나 `motion-rules.md`·`seek-pattern.md` 와 부딪치면 우리 규칙을 따른다. 그 기법을 쓰지 않거나 규칙 안의 방법으로 근사한다. 기법 때문에 규칙의 예외를 사용자에게 묻지 않는다.

## 화면 코드로 옮길 때 (5단계)

- aimotion 의 파일을 불러오지 않는다. 원리를 읽고 `src/index.html` 에 다시 쓴다. 우리 규칙(`seek-pattern.md`)이 먼저다.
- 시계 대응
  - 데모의 `setup()` 굽기 → 로드 때 한 번 (첫 `seek(0)` 전)
  - `frame(t)` → `window.seek(t)`
  - `rand(seed)` → 우리 씨앗 난수
  - `track`·`ease` 키프레임 → `seek-pattern.md` 의 도우미 (`pr` `lerp` `eo` 등)
  - 상태가 쌓이는 시뮬레이션 → 로드 때 고정 dt 로 구워 배열·canvas 에 두고 t 로 읽는다. `render.mjs` 는 프레임을 순서 없이 찍는다
- 좌표 · 데모의 1080·1920 은 데모 무대의 값이다. 우리 무대(기본 1920×1080)에 맞춰 다시 계산한다.
- 라이브러리 · 우리 영상은 `vendor/` 의 three.js 와 키트만 쓴다. CDN 은 금지다. 데모가 쓴 라이브러리는 색인 발췌의 "라이브러리"·"옮길 때 주의"에 적혀 있다.
  - GSAP·anime.js·Motion·mo.js·lottie → 타임라인의 구조만 가져와 t 의 식으로 쓴다
  - opentype.js·d3·Paper.js·p5.js·Zdog·PixiJS·Babylon.js·rough.js → 원리만 가져와 DOM·SVG·canvas·내장 three.js 로 쓴다
  - Rapier2D·matter-js 물리 → 닫힌 식으로 되면 닫힌 식을 쓴다. 안 되면 직접 짠 고정 dt 계산으로 로드 때 굽는다
  - 실제 지도 데이터(world-atlas) → 쓰지 않는다. 직접 그린 양식화된 지도로 바꾼다
  - Web Audio·Tone.js 합성 → 쓰지 않는다. 소리는 ElevenLabs 나 직접 넣은 음원으로 만든다(고정 규칙). 소리에 그림을 맞추는 방식만 참고한다 (`src/beats.js`)
- 손으로 쓴 WebGL2 셰이더(49편) · `seek-pattern.md` `## three.js` 의 조건(3D 톤과 클레이·판화·HUD 의 입체판)에 맞으면 내장 three.js 의 `ShaderMaterial` 로 옮긴다. 조건 밖이면 canvas 2D·SVG 로 근사한다(로드 때 굽기). 근사가 안 되면 그 기법을 쓰지 않는다.
- 글자를 canvas·3D 에 그리는 기법(거리장·입자·연체 글자 등) · `seek-pattern.md` 의 글자 규칙(글자는 DOM 층에 쓴다)과 부딪친다. 글자는 DOM 층에 두고 효과만 canvas·3D 로 만든다. 그렇게 나눌 수 없으면 그 기법을 쓰지 않는다.
- 출처 표기 · 기법을 구현한 코드(알고리즘·셰이더·굽기)를 옮겨 쓰면 그 코드 위에 한 줄을 적는다. `// aimotion <id> 의 <기법> 을 옮김 (MIT © 2026 kstost, github.com/kstost/cokacmotion)`
- 6단계 `--det` 에 옮긴 기법이 나오는 구간의 시각을 넣는다.
- 8단계 보고에 쓴 기법의 id, 가져온 기술, 가져오지 않은 것을 적는다.

## 색인과 갱신

- 색인 항목에는 `kind: "technique"`, `tech`(기법 이름), `group`(분류), `notes`(구현 노트 주소)가 더 있다. `video` 는 비어 있고 `url` 이 데모 페이지다.
- aimotion 에 데모가 늘면 `node scripts/refs.mjs index --only am` 으로 `am:` 항목만 다시 받는다. 다른 출처 항목과 `built` 날짜는 그대로 남는다. 이어서 `node scripts/refs.mjs verify` 를 실행한다. 데모 페이지가 열리면 `via: page` 로 적힌다.
- 새로 생긴 데모는 톤 판정 전이라 `search --tech` 에 나오지 않는다. 포스터와 목록의 장면 설명을 보고 `references/tone-labels.json` 에 판정을 넣는다(`by: "poster"`). 그 기법을 쓸 수 있는 톤을 2개까지 적는다. 톤과 무관하면 `tones` 를 비우고 `note` 를 "해당 없음:" 으로 시작한다.
- 기법에는 `new` 를 붙이지 않는다. `new` 는 카탈로그에서 사용자 리뷰를 기다리는 스타일 레퍼런스의 표시다. 기법의 톤 판정은 에이전트가 붙였다. 틀린 판정을 찾으면 고친다.
- 쓰지 않을 기법은 `references/ref-videos.json` 에 `excluded` 로 적는다. 그러면 `search --tech` 에서 빠진다.
