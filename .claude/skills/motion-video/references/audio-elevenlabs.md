# 소리 만들기 (ElevenLabs MCP)

이 문서는 소리 방식이 `ElevenLabs` 일 때만 쓴다. 커넥터가 없으면 `SKILL.md` 0단계의 `직접 음원` 이나 `무음` 으로 만든다. 3절의 `audio-probe.py` 측정과 `video.json` 형식은 직접 넣은 음원에도 그대로 쓴다.

도구 이름은 `mcp__claude_ai_Elevenlabs__creative_*` 다. 지연 로드 도구면 필요한 것을 `ToolSearch` 한 번에 묶어 불러온다.
`creative_create_flow, creative_list_voices, creative_generate_speech, creative_add_flow_node, creative_run_flow_nodes, creative_get_flow_run_status`

## 공통

- `creative_create_flow` 를 먼저 부르고 그 `flow_id` 를 모든 호출에 넘긴다.
- 생성 호출은 바로 돌아온다. `creative_get_flow_run_status` 로 끝났는지 확인한다.
- 상태 응답은 매우 길다(서명된 URL 이 여러 번 들어 있다). 생성 직후 연달아 부르지 않는다. 다른 작업을 하나 한 뒤에 한 번 부른다.
- 생성 호출을 재시도 목적으로 다시 부르지 않는다. 다시 부르면 크레딧이 한 번 더 나간다.
- 결과의 `content_url` 은 2시간 뒤에 만료된다. 끝나면 바로 `curl -sL -o` 로 `assets/` 에 내려받는다.

## 1. 내레이션

1. `creative_list_voices` 에 `languages: ["ko"]` 와 성별·나이를 준다. 스토리보드의 목소리 설명에 맞는 것을 고르고, 고른 이름을 보고에 적는다.
2. `creative_generate_speech`, `model_id: "eleven_v4"`, `generations_count: 2`. 원고는 스토리보드의 "읽는 소리로 적은 원고"를 쓴다. 문장 사이에 빈 줄을 넣는다.
   기본값 4개로 부르면 동시 실행 한도(concurrency limit)에 걸려 하나가 대기 상태로 오래 남는다. 대기 중인 것은 기다리지 않고 완료된 것만 쓴다.
3. 완료된 것 2개를 내려받아 `python3 scripts/audio-probe.py <파일>` 로 잰다. 문장 사이 무음이 뚜렷한 쪽을 쓴다.
   무음 기준은 파일마다 자동으로 잡는다(바닥 소음 + 4dB, 0.15초 이상). 출력의 `silences (기준 …)` 를 본다. 문장 수보다 쉼이 적게 잡히면 `--silence <dB>` 를 1~2dB 올려 다시 잰다. 쉼이 잘게 쪼개지는 결과는 쓰지 않는다.
4. 무음 구간의 가운데를 문장 경계로 삼는다. `video.json` 의 `voice.segments` 에 `[원본 시작, 원본 끝, 영상에서의 시작]` 을 적는다.
5. 문장 사이에 0.6~0.9초를 더해 장면이 숨 쉴 시간을 만든다. 첫 문장은 1.0~1.2초에 시작한다. 마지막 문장 뒤에 2초 이상 남긴다.
6. 이 시각이 장면 시작 시각이 된다. 영상 길이는 여기서 정해진다.
7. 화면 문구를 대사의 특정 단어에 맞춰야 하면 `python3 scripts/audio-probe.py <내레이션> --words` 로 단어 시각을 잰다. 로컬 whisper 라 크레딧이 들지 않는다. 원본 시각이므로 `voice.segments` 로 영상 시각으로 바꿔 쓴다.

## 2. 음악

장면 시각이 정해진 뒤에 만든다.

1. `creative_add_flow_node`, `node_type: "music"`, `model_id: "eleven_music_v2_5"`,
   `model_parameters: {"duration_seconds": <영상 길이+3>, "lyrics_type": "instrumental", "instrumental": true}`. `cut` 으로 줄일 여유를 둔다.
2. 프롬프트는 소리만 묘사한다. 장르, BPM, 악기, 그리고 초 단위 흐름을 적는다.
   시네마틱 3D 는 정점 큰 타격 바로 앞 0.3~0.6초를 음악이 크게 줄어드는 구간으로 프롬프트에 적는다(완전한 무음이 아니라 약 −30dB, 바닥 소리는 남는다). 결과가 따랐는지는 `audio-probe.py --step 0.25` 의 음량 곡선으로 본다.
   악기는 `tone-catalog.md` 에서 그 톤의 색·질감 칸 끝 `소리 ·` 의 악기에서 고른다. 도입에는 그 가운데 1~2개만 쓴다. 타악기·킥은 도입에 넣지 않는다(킥은 가속 구간부터). 생성 결과가 악기 지시를 따랐는지는 측정하지 못한다. 보고에 그렇게 적는다.
   "First 5 seconds … From 5 seconds … From 17 seconds … From 22 to 27 seconds the biggest peak … At 28 seconds one resolved chord that rings out."
   생성 결과는 이 시각을 자주 따르지 않는다. 고조가 몇 초 일찍 오거나 늦게 온다. 다시 만들지 말고 6번의 `delay`·`cut`·`repeat` 로 맞춘다.
3. `creative_run_flow_nodes` 를 `generations_count: 2` 로 부른다.
4. 둘 다 내려받아 `audio-probe.py --step 2` 로 음량 곡선을 본다. 도입이 조용하고 뒤로 갈수록 커지는 쪽을 고른다.
5. 고른 쪽을 `--step 0.25` 로 다시 재서 세 시각을 찾는다. 소리가 처음 들어오는 시각, 음량이 뛰는 시각(고조), 음량이 떨어지기 시작하는 시각(종결 화음).
6. 장면에 맞춘다.
   박과 마디 길이는 `python3 scripts/audio-probe.py <음악> --onsets` 의 `downbeats` 줄에서 읽는다. `60/BPM` 을 손으로 계산하지 않는다.
   - `downbeats (박 <BPM>, 마디 <초>, 저역 배율 <값>) <시각> <시각> ...` 의 시각은 곡 시각의 마디 첫 박이다(4/4 로 본다).
   - 이 줄의 BPM 은 `bpm` 줄보다 정밀하다. `bpm` 줄은 박 간격을 11.6ms 단위로 재므로 곡 뒤쪽에서 박이 밀린다. (예 · `occams-razor` 의 쓰지 않은 후보 곡 `bgm_a.mp3` 는 `bpm` 줄 90.7, `downbeats` 89.97 BPM 이었다. 큰 타격이 박 격자 ±35ms 안에 닿는 비율은 29% 에서 68% 로 올랐다. 측정값이다)
   - `저역 배율` 이 1.5 보다 작으면 네 박의 저역이 비슷하다. 이때는 어느 박이 마디 첫 박인지 믿지 않는다(영상 15편의 음악 가운데 11곡이 1.00~1.38, 4곡이 1.54~2.18 이었다. 측정값이다). 박 격자와 마디 길이만 쓰고, 마디의 시작은 음량 곡선의 고조 시각에 가장 가까운 박으로 정한다.

   먼저 `정점 장면 시작 - 음악의 고조 시각` 을 계산한다.
   - 이 값이 0~3초면 · `delay` 에 그대로 넣는다.
   - 이 값이 음수면(고조가 늦게 온다) · `cut: [0, <당길 길이>]` 로 도입을 잘라 당긴다. 당길 길이는 마디의 정수배로 맞춘다.
   - 이 값이 3초보다 크면(고조가 일찍 온다) · `delay` 로 밀면 앞이 빈다. `delay` 는 3초 안에서 쓰고, 남는 길이는 `repeat: [반복 시작, 길이, 횟수]` 로 고조 앞의 한 마디를 반복해 채운다. 반복 시작은 고조 시각에서 마디의 정수배만큼 앞이다.
   - `delay` · 고조 시각을 정점 장면의 시작에 맞추는 값이다.
   - `cut` · 종결 화음이 마지막 장면 시작보다 늦으면 정점 구간에서 박자 단위로 잘라낸다. 한 박의 길이는 `downbeats` 줄의 `마디` ÷ 4 다. 4박(한 마디)이나 8박을 자른다. 자르는 시작점은 고조 시각에서 박의 정수배만큼 뒤로 잡는다.
   - `cut`·`repeat` 의 길이는 `downbeats` 줄의 `마디` 값의 정수배로 적는다. (예 · 첫 작업 영상의 `cut` 길이 2.034초는 `downbeats` 의 마디 2.033초와 1ms 차이다) 시작점은 위의 경우별 규칙을 따른다(도입 당김은 0, 정점 `cut` 은 고조 시각에서 박의 정수배만큼 뒤, `repeat` 은 고조 시각에서 마디의 정수배만큼 앞).
   - `downbeats`·`hits` 줄의 시각은 `cut` 을 적용하기 전의 곡 시각이다. `cut` 뒤에 오는 `repeat` 의 시작은 그 곡 시각에서 `cut` 길이를 뺀 값으로 적는다.
   - `intro_boost` · 도입이 -35dB 보다 조용하면 `[4, <소리가 들어오는 시각>]` 으로 올린다.
   - `gain` · `[시작 음량, 정점 음량, 올리기 시작, 올리는 시간]`. 정점 직전 5초 동안 0.5 → 0.9 로 올린다.
   - `repeat` · 곡이 영상보다 짧을 때도 쓴다. 정점 구간의 한 마디를 반복하면 끝이 비지 않는다. `cut` 과 함께 쓸 수 있다. 이때 `repeat` 의 시각은 `cut` 을 적용한 뒤의 곡 시각이다.
   - 음악이 끝나는 시각은 `delay + 곡 길이 - cut 길이 + repeat 길이×횟수` 다. 이 값이 영상 길이보다 짧으면 끝이 빈다.
   - 값을 정한 뒤 `audio-probe.py <음악> --fit <정점 전환 시각들> --video videos/<id>` 로 지금 `delay` 의 전환별 오차를 본다. 오차가 1프레임(30fps 에서 33ms)을 넘는 전환은 `motion-rules.md` 의 `## 음악 박자 맞춤` 대로 처리한다. `--fit` 은 `video.json` 을 고치지 않는다.

## 3. 효과음

1. `creative_add_flow_node`, `node_type: "sfx"`, `model_id: "eleven_text_to_sound_v2"`,
   `model_parameters: {"duration_seconds": 0.5~2, "prompt_influence": 0.5}`.
2. 3종 안팎을 만든다. 등장음(짧은 클릭), 전환음(짧은 whoosh), 주제에 맞는 소리 하나. 주제에 맞는 소리는 `tone-catalog.md` 그 톤의 `소리 ·` 의 효과음에서 고른다.
3. `creative_run_flow_nodes` 를 `generations_count: 2` 로 한 번에 부른다.
4. `video.json` 의 `sfx` 에 `[파일, 시각, 음량, 동기점]` 을 적는다. 클릭 0.4~0.55, whoosh 0.3 안팎. 효과음은 음악보다 작게 둔다.
   - 동기점은 파일 안의 어느 지점을 시각 칸에 놓을지다 · `"onset"`(첫 타격), `"peak"`(최고점), 숫자(파일의 그 초).
   - 시각 칸은 화면 사건 시각에서 앞당길 만큼 뺀 값이다 · 시각 = 사건 시각 − 프레임 수 / fps. 사건 시각은 그 움직임이 시작하는 프레임이다.
   - 값은 `python3 scripts/audio-probe.py <파일> --peak` 로 본다. 최고점은 10ms 음량을 50ms 로 평균한 곡선의 가장 큰 곳, 첫 타격은 그보다 20dB 작은 소리를 처음 넘는 곳이다. 꼭대기가 평평한 소리는 최고점이 흔들리므로 `"onset"` 을 쓴다.
   - 동기점을 빼면(3칸) 지금까지처럼 파일 시작을 시각 칸에 놓는다. 기존 영상의 sfx 줄을 4칸 형식으로 옮겨 적지 않는다. 수정 요청으로 시각·음량을 고치는 것은 된다.
5. 배치 기본값. 사용자가 승인한 본보기를 따른다. 출처마다 값이 달라서다(mg-styles-15 는 whoosh 최고점을 사건 시각에, motion-graphics 는 파일 시작을 2프레임 앞에 둔다 · 이 whoosh 면 최고점이 사건 약 6프레임 뒤).
   - whoosh · `"peak"` 를 전환 움직임 시작 4프레임 앞에 둔다. 첫 작업 영상의 실측값이다(최고점 16.71초, 전환 시작 16.85초)
   - 클릭·도장 · `"onset"` 을 사건 1프레임 앞에 둔다(mg-styles-15 08-morph)
   - riser · 끝을 타격 시각에 둔다. 동기점에 파일 길이(초)를 숫자로 적는다
   - 청취 의견은 8단계 보고의 "직접 들어 볼 시각"으로 받는다. 묻고 멈추지 않는다

## 4. 믹스 확인

`python3 scripts/mix.py videos/<id>` 는 믹스 뒤에 세 가지를 재서 출력한다. `경고 없음` 이 나올 때까지 `video.json` 만 고치고 `mix.py` 를 다시 실행한다. 프레임을 다시 찍을 필요는 없다.

| 경고 | 고치는 법 |
|---|---|
| 음악이 N초에 끝난다 | `repeat` 로 정점 구간을 늘린다. `cut` 을 썼으면 자르는 길이를 줄인다 |
| N초부터 끝까지 거의 무음이다 | 위와 같다. 음악이 길면 마지막 장면이 너무 긴지 본다 |
| 목소리가 음악에 묻힌다 | `voice.gain`(기본 1.5)을 올린다. 2.5~4 가 흔하다. 그래도 모자라면 `music.gain` 의 정점 음량을 내린다 |

목소리 비교는 대사 사이 쉼(음악만 나오는 구간)과 대사 구간의 음량 차이다. 4dB 이상이어야 한다. 쉼이 짧아 비교하지 못하면 그렇다고 출력한다.

그다음 `audio-probe.py renders/video.mp4 --step 2` 로 모양을 본다.

- 정점 구간의 음량이 도입보다 5dB 이상 크다.
- 마지막 2초는 음량이 떨어진다.
- 그렇지 않으면 `gain` 과 `duck`(기본 2.5, 낮출수록 음악이 덜 눌린다)을 고친다.
