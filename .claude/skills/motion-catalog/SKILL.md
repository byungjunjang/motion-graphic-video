# motion-catalog

입력은 없어도 된다. 카탈로그에서 사용자가 레퍼런스 1개와 소개할 대상을 함께 보낸다.
출력은 `videos/<id>/renders/video.mp4` 다. 기본값은 `motion-video` 와 같다.

`motion-video` 와 다른 점은 2단계 하나다. 에이전트가 후보 6개를 고르지 않는다. 사용자가 카탈로그 전체에서 직접 고른다.
사람이 확인하는 지점은 두 곳이다. **카탈로그 선택**(1단계)과 **스토리보드 승인**(`motion-video` 3단계).

시작하기 전에 `.claude/skills/motion-video/SKILL.md` 를 읽는다. 아래에서 "mv N단계"는 그 문서의 N단계다.

## 0. 준비

```bash
[ -d node_modules/playwright-core ] || npm i
[ -f references/ref-index.json ] || node scripts/refs.mjs index
```

색인의 `built` 날짜가 30일보다 오래됐으면 mv 0단계대로 색인을 다시 만든다.
mv 0단계의 마지막 줄대로 소리 방식(`ElevenLabs` · `직접 음원` · `합성` · `무음`)을 정한다.

## 1. 카탈로그 → 사용자가 선택 (확인 지점 1)

1. `node scripts/catalog.mjs` 를 **백그라운드로** 실행한다 (Bash `run_in_background`). `references/catalog.html` 이 브라우저에 열린다.
   레퍼런스가 톤별 장(章)으로 묶여 나온다. 왼쪽 목록에서 장을 고른다. 장마다 맞는 콘텐츠·색·움직임 설명이 있다. 우리 영상으로 확인한 톤의 장에는 "쓰지 않는 것"도 나온다. 카드에 마우스를 올리면 영상이 재생된다.
   카드 표시는 "새 항목", "실자료 필요", "AI 이미지 필요" 셋이다. 표현 기법(`am:`)은 카탈로그에 나오지 않는다. 제작 단계에서 에이전트가 찾아 쓴다(mv 3단계). 사용자는 기법을 지시하지 않는다.
2. 채팅에는 장 목록과 장마다 편수를 한 줄로 적는다. "카드를 눌러 소개할 대상을 적고 '이 스타일로 만들기'를 누르세요"라고 알린 뒤 턴을 끝낸다.
   사용자가 대상을 이미 말했으면 그 대상을 채팅에 다시 적고, 화면의 입력 칸에도 같은 내용을 적으라고 알린다.
3. 사용자가 단추를 누르면 명령이 끝나고 `videos/.catalog-choice.json` 이 생긴다. 필드는 `id`, `no`, `tone`(톤 id), `note`(카드 제목), `subject`(소개할 대상), `memo` 다.
   사용자가 화면 대신 채팅으로 답하면 그 답을 쓴다. 답을 받기 전에는 2단계로 가지 않는다.

원격 채널(Telegram·Slack)처럼 브라우저를 볼 수 없는 환경이면 1번을 `--no-open` 으로 실행하고 `references/catalog.html` 파일을 보낸다.
사용자가 파일을 열어 단추를 누르면 답이 클립보드에 복사된다. 사용자가 채팅에 붙여 넣은 답을 쓴다.
배포한 카탈로그(주소는 프로젝트 `CLAUDE.md` 의 `## 카탈로그 배포`)가 지금 색인과 같으면 파일 대신 그 주소를 보내도 된다. 색인·톤 판정을 바꾼 뒤 다시 배포하지 않았으면 파일을 보낸다.

## 2. 영상 폴더 → 고른 레퍼런스 읽기

1. `subject` 로 `<id>` 를 짓는다. 영어 소문자와 하이픈만 쓴다. 이미 있는 폴더면 다른 이름을 짓는다.
2. 폴더를 만든다.

   ```bash
   mkdir -p videos/<id>/{src,refs,renders,assets/{fonts,voice,bgm,sfx}}
   cp templates/starter/assets/fonts/* videos/<id>/assets/fonts/
   mv videos/.catalog-choice.json videos/<id>/refs/choice.json
   ```

3. `node scripts/refs.mjs show <레퍼런스 id>` 로 전문을 읽는다. 카드 제목과 발췌만 보고 진행하지 않는다. `lo:` 항목이면 `show lo:<slug> --demo` 로 DEMO.md 전체(숏 표·음악 구조)까지 읽는다.
   `references/tone-labels.json` 에서 그 id 의 `flags` 를 본다. 표시의 정의는 `tone-catalog.md` 의 표시(`flags`) 줄에 있다.
   - `실자료`(카탈로그 카드의 "실자료 필요") 면 사용자에게 실제 자료를 요청한다.
     전문에서 그 레퍼런스가 쓰는 실제 자료의 종류를 뽑는다(촬영본·사진·기록 문서·위성 사진·제품 3D 파일 등). 소개할 대상에서 그에 상응하는 자료를 종류와 수량으로 적어 채팅으로 요청한다(예 · 제품 사진 5장 이상, 현장 촬영본 10초 이상 2개).
     4번에서 묻는 것이 있으면 같은 메시지에 넣는다. 답을 받기 전에는 3단계로 가지 않는다.
     받은 자료는 `videos/<id>/assets/` 에 두고 `file` 로 해상도를 확인해 `FACTS.md` 에 적는다(mv 1단계 4번). 로고·제품 이미지는 사용자가 준 파일만 쓴다(고정 규칙).
     사용자가 자료가 없다고 답하면 실자료 부분을 그림·도형으로 대신하는 안을 스토리보드 `## 방향` 에 적고(그림으로는 원본의 모습을 재현하지 못한다. 대체안은 레퍼런스의 구조·박자·전환·타이포 처리만 따른다), 스토리보드 승인(확인 지점 2)에서 함께 승인받는다. 사용자가 그때 자료를 주면 그 자료를 쓴다.
   - `실존` 은 카탈로그 화면에 나오지 않는다. 에이전트가 지키는 규칙이다. 그 대상의 모습·이름·로고를 그리지 않는다. 구조·박자·전환·타이포 처리는 가져온다. 사용자에게 따로 묻지 않는다.
   - `AI이미지`(카탈로그 카드의 "AI 이미지 필요") 면 인물·사물·풍경 일러스트를 AI 이미지로 그린다. 순서는 `.claude/skills/motion-video/references/ai-image.md` 다. 디자인 시트와 장면 그림은 mv 3단계에서 스토리보드에 붙여 확인받는다. 사용자에게 따로 묻지 않는다. Codex 로그인이 안 되어 있을 때만 알린다.
4. `subject` 가 비었거나 URL·이름이 없어 대상을 특정할 수 없으면 채팅으로 묻는다. 답을 받기 전에는 3단계로 가지 않는다.

## 3. 제작 (mv 1, 3~8단계)

mv 1단계(사실 확인)부터 mv 8단계(보고)까지 순서대로 한다. mv 2단계는 건너뛴다. 아래만 다르다.

- mv 3단계 `## 레퍼런스` · 고른 항목의 id, 카드 번호(`no`), 전문에서 가져올 것(구조·박자·전환·타이포 처리)을 적는다. `memo` 가 있으면 함께 적는다.
- mv 3단계 `## 방향` · 톤은 `choice.json` 의 `tone` 을 쓴다. 사용자가 직접 고른 톤이므로 조용히 바꾸지 않는다.
  대상에 맞지 않는다고 판단하면 스토리보드를 보여 줄 때 이유와 대안 톤 1개를 채팅에 적고 사용자의 답을 받는다.
- mv 3단계 장면표 · 장면 수와 길이는 레퍼런스가 아니라 mv 기본값(30~40초)을 따른다. 사용자가 `memo` 나 `subject` 에 길이를 적었으면 그 길이를 쓴다.
- mv 8단계 보고 · "카탈로그에서 고른 레퍼런스"와 "레퍼런스에서 가져온 것 / 가져오지 않은 것"을 함께 적는다.

레퍼런스의 문장과 브랜드 이름은 베끼지 않는다. 구조·박자·전환·타이포 처리만 가져온다.
표현 기법(`am:`)에서는 효과를 만드는 방법만 가져온다. 데모의 소재·장면·구도·문구·색·세로 형식은 옮기지 않는다.

## 수정 요청

mv 의 `## 수정 요청` 표를 따른다. 레퍼런스를 바꾸고 싶다고 하면 1단계부터 다시 하고, 기존 `refs/choice.json` 은 `refs/choice-<날짜>.json` 으로 이름을 바꿔 둔다.
