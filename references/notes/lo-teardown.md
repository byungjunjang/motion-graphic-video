# 분해도 제품 영상 · 층이 떠오르고 카메라가 그 사이로 들어간다 — 분석 노트

> 거의 검은 무대 위의 39초 제품 영상. 반쪽짜리 기계식 자판 하나를 아주 낮은 눈높이에서 훑으며 시작하고, 주황 키 하나가 한 번 눌린 뒤, 키캡·스위치·판·회로 기판·기둥·바닥 케이스 여섯 층이 한 축으로 떠올라 벌어진다. 오른쪽 세로 열에 층마다 이름과 숫자가 붙고, 카메라가 층 사이로 파고들어 기판 뒷면의 칩과 조명 소자를 가까이서 본다. 끝에 층이 아래부터 다시 닫히고 완성품 위에 치수선이 그려진다. 하드웨어 출시, 제품 상세, 사양 설명처럼 "속을 열어 숫자로 보여 주는" 영상에 맞는다.

출처 · lo:teardown. 색인에 든 원래 글은 약 6천 자의 스타일 명세다(본질, 움직임, 카메라 문법, 함정, 시각이 붙은 숏 표 13개). 글은 제품의 설계 파일에서 형상과 숫자를 가져오라고 정했고, 분리·닫힘 곡선, 카메라 거리(밀리미터), 이름표 그리기 순서를 자세히 정했다. 그러나 색 값, 화면 안에서 제품과 이름표 열이 차지하는 자리와 크기, 글자 크기, 배경의 밝기가 없다. 그래서 영상 프레임을 보고 이 노트를 썼다. 원래 글의 숏 표 시각은 화면과 맞는다. 여기서는 화면 숫자와 원래 글과 다른 점만 더한다.
측정 · 파일 1280x720 · 24fps · 38.75초. 크기는 1920x1080 기준으로 바꿔 적는다(1.5배). 하드 컷은 없다(장면 감지 0회). 움직임 세기는 평균 11.4, 중앙값 6.9 이고, 1 아래인 칸은 8% 뿐이다. 카메라가 거의 쉬지 않는다. 큰 구간은 25.0초(44.2 최대, 빠른 물러나기), 21.0~21.5초(42.6·40.0, 층을 지나 올라가기), 14.0초(41.0, 층 사이로 파고들기), 2.5~3.0초(32.0~32.7, 낮은 훑기에서 들어 올리기), 18.0초(29.8, 기판 아래 미끄러지기)다. 28.0~33.0초는 0.7~1.7, 36.0초부터 끝까지 0.9~1.0 으로 아주 느리게 흐른다. 색 값은 프레임에서 잰 근삿값이다.
소리 · 듣지 못했다. 측정값만 적는다. BPM 95.7, 마디 검출 96.01 BPM(마디 2.500초). 원래 글의 96 과 맞는다. 마디 첫 박은 2.48, 4.98, 7.48 … 24.98초다. 가장 큰 타격(세기 1.00)은 3.11초다. 원래 글의 키 한 번 누르기 시각(3.13초)과 맞는다. 음량이 가장 큰 칸은 5.0초(-10dB, 층이 떠오르는 순간)와 26.5초(-11dB, 층이 닫히는 순간)다. 무음은 4.30~4.92초(원래 글의 첫 쉼 4.4~5.0초), 24.08~25.00초(원래 글은 24.6~25.0초로 적었으나 측정은 0.5초 더 길다), 13.42~14.94초(파고들기 직전·직후 두 토막), 17.68~18.58초다.

## 3. 움직임

- 원래 글의 분리 곡선(느린 시작, 빠른 가운데, 긴 안착), 층 사이 0.15~0.2초 차이, 귀퉁이부터의 물결, 닫힘은 아래부터 더 빠르게, 키의 실제 눌림은 화면과 맞다. 되풀이하지 않는다.
- 영상에서 확인한 점 · 카메라는 33초 동안 사실상 멈추지 않는다. 움직임 세기 1 아래인 칸은 전체의 8% 이고, 대부분 끝 화면과 치수선 장면이다. 원래 글이 접사에서 멈춘다고 정한 것은 사물이다. 카메라는 접사에서도 느리게 흐른다(15~17초 6.5~11.1).

## 4. 전환

- 컷이 없다. 장면은 모두 사물 속을 지나는 카메라 이동이다. 원래 글에 있다.
- 영상에서 확인한 점 · 접사로 들어가고 나올 때 화면 전체가 기판·스위치로 덮이는 프레임(13.5초, 22초)이 있다. 이 프레임이 컷 대신 장면을 가른다.
- 자막은 장면이 바뀔 때 갈아 끼운다. 이름표는 카메라가 다시 움직이기 전에 사라진다(12초, 18초).

## 5. 타이포

- 이름표 · 오른쪽 세로 열(가로 74~82%). 줄마다 세 부분이다 · 왼쪽 작은 빨간 순번(높이 약 1%), 이름(산세리프 굵은 체, 높이 약 2.5%·약 27px), 그 아래 사양 한 줄(고정폭, 높이 약 1%, 회색). 여섯 줄이 세로 18~79% 에 놓이고, 각 줄은 자기 층 높이에 맞춘다. 사물의 점에서 가는 회색 선(굵기 약 1.5px)이 수평으로 열까지 온다.
- 자막 · 화면 아래 가운데(세로 92~96%). 위 줄 첫 언어 굵은 체 약 2.4%(흰색), 아래 줄 번역 약 1.4%(회색). 원래 글이 정한 자막 자리(화면 아래 12%)와 맞다.
- 치수선 숫자 · 고정폭 약 1.6%, 치수선 방향으로 기울어 사물의 원근을 따른다. 위에 아주 작은 회색 머리말.
- 끝 제목 · 왼쪽(가로 8~27%, 세로 36~44%). 첫 언어 가는 체 큰 글자 약 7.9%(약 85px), 위에 짧은 빨간 가로줄, 아래 작은 영문 한 줄 약 3%, 그 아래 고정폭 크레딧 3줄(약 1%).

## 6. 가져올 것

- 12초 판에서 꼭 남길 대표 장면 · 원본 4.5~10.0초의 "닫힌 제품이 마디 첫 박에 귀퉁이부터 물결로 떠올라 여섯 층으로 벌어지고, 제품 중심이 가로 48% 에서 41% 로 왼쪽에 옮겨 가며, 오른쪽 열(가로 74~82%)에 층마다 순번·이름·사양 이름표 여섯 줄이 0.35초 간격으로 서는" 장면이다. 정지 화면에서 분해된 제품이 화면 높이의 74% 를 차지한다. 층이 한 축으로 고르게 벌어지지 않으면, 숫자가 사물에서 떨어진 표로 나오면, 카메라가 멈추면 이 영상이 아니다.
- 12초 판 압축 예 · 0~1.5초 낮은 훑기(빛이 키캡 위를 지난다), 1.5~2.5초 강조 키 한 번 누르기와 들어 올리기, 2.5~6.5초 대표 장면 4초(떠오르기와 왼쪽 옮기기 1.5 + 이름표 여섯 줄 2.0 + 정지 0.5), 6.5~7.5초 층 사이로 파고들기, 7.5~9.0초 부품 하나 접사와 이름표 하나, 9.0~10.0초 빠른 물러나기와 닫힘(키캡 물결이 마지막), 10.0~12.0초 치수선 두 개와 끝 제목. 조명 소자 장면, 스위치 아래 장면, 층을 지나 올라가기는 뺀다.
- 숫자를 사물에 붙인다. 이름표는 점·선·글자로, 치수는 사물의 원근 위에 그린다.
- 큰 이동 앞의 짧은 무음.

## 7. 함정

- 이 영상의 제품은 실존하는 공개 설계 자판이다. 끝 크레딧에 실존 설계 이름과 공개 허가 표기가 있고, 기판 접사 이름표에 실존 칩 모델명이 있다. 쓰지 않는다. 화면의 자막·이름표 문장도 옮기지 않는다. 역할(층 이름, 사양 한 줄, 부품 이름, 치수)만 가져온다.
- 원래 글은 설계 파일이 주는 숫자만 쓰라고 정했다. 이 저장소의 사실 규칙도 같다. 사용자가 제품의 설계 파일이나 사양서를 주면 거기서 직접 확인한 숫자만 이름표와 치수에 쓴다. 파일이 없으면 숫자 없는 이름표(층 이름만)로 만들거나, 가상의 제품으로 만들고 연출이라고 밝힌다.
- 실존 제품의 겉모양을 흉내 내어 모델링하지 않는다. 사용자의 제품이면 사용자가 준 형상·사진으로, 아니면 일반적인 형태(둥근 판, 일반 부품)로 만든다. 부품 윗면에 실존 로고·모델명을 그리지 않는다.
- 검은 바탕에 검은 부품이 묻힌다. 검은 플라스틱은 #1A1A1C 이상으로 올리고 뒤쪽 테두리 빛으로 윤곽을 낸다.
- 카메라를 멈추면 제품 사진 넘기기가 된다. 장면 사이 이동을 컷으로 바꾸지 않는다. 접사에서도 카메라를 초당 화면 폭의 1~2% 로 흐르게 한다.
- 이름표를 제품 위에 겹치면 읽히지 않는다. 제품을 화면 왼쪽 60% 안에 두고 이름표는 오른쪽 열에 둔다. 제품을 옮기지 말고 카메라 투영의 가로 오프셋(three.js `setViewOffset`)으로 옮긴다.

## 8. 코드로 재현 못 하는 요소와 대체 방법

값은 1920x1080 기준이다. three.js(`vendor/three`)와 `vendor/three-looks/looks.js` 를 쓴다.

| 요소 | 왜 어려운가 | 대체 방법(구체 값) | 대체하면 잃는 것 |
|---|---|---|---|
| 실제 설계 파일에서 만든 형상 | 이 저장소에는 설계 파일을 읽는 도구가 없다 | 층을 단순 형상으로 만든다. 판·기판·케이스는 외곽선을 `THREE.Shape` 로 그려 `ExtrudeGeometry`(두께 비율 판 1.6, 기판 1.6, 케이스 바닥 2.0)로 밀어낸다. 키캡은 `LOOKS.slab(w, h, d, r)` 로 만든 둥근 판을 위로 갈수록 좁히고(윗면 0.75배) InstancedMesh 로 21개. 스위치·기둥도 InstancedMesh. 사용자가 실제 치수를 주면 그 값만 쓴다 | 실제 부품의 세부(구멍 위치, 핀, 소자 배치)의 정확함 |
| 사진 같은 재질과 스튜디오 빛 | 실제 주변광 사진과 물리 기반 렌더러 | `scene.environment = LOOKS.env(gl, 'studio')` 를 바탕으로 쓰되 배경은 #010303 → #141518 방사형 그라데이션 판을 따로 둔다. 키캡 MeshPhysicalMaterial(거칠기 0.55, 색 #D8D0C8), 강조 키 #E07858, 케이스 거칠기 0.25 금속성 0, 금색 패드 금속성 1 거칠기 0.35 색 #C8A060. 앞 왼쪽 위 주 빛 + 뒤쪽 차가운 테두리 빛(#9FB4D0, 세기 주 빛의 0.6). 후처리 `LOOKS.post(gl, { w: 1920, h: 1080, tone: 'aces', bloom: 0.25, threshold: 1.2, vignette: 0.45, grain: 0.02 })` | 실제 렌더러의 부드러운 반사 |
| 바닥 접촉 그림자 | 보이지 않는 바닥에 그림자만 | `LOOKS.floor()` 로 그림자만 받는 바닥을 두고 점 격자는 끈다(격자가 보이면 설계도가 된다) | 없음 |
| 층 분리·닫힘과 물결 | 없다. 코드로 된다 | 층 i 의 높이 = 기본 높이 + 간격 x ease(구간 진행). 곡선은 3차 가속·감속(`u<.5 ? 4u³ : 1-(-2u+2)³/2`). 위 층부터 0.18초 차이, 키캡은 뒤 왼쪽 귀퉁이에서 거리 순으로 0.02초씩 늦게. 닫힘은 아래 층부터 층마다 1.0초. 마지막 키캡은 앉은 뒤 눌림 거리만큼 내려갔다 0.12초에 돌아온다 | 없음 |
| 이어지는 카메라 경로 | `LOOKS.fly` 는 구간 사이를 빠르게 건너뛰는 방식이라 원본의 끊김 없는 이동과 다르다 | 카메라 위치·주시점 키를 시각과 함께 적고 성분마다 단조 3차 보간(넘침 없는 보간)으로 잇는다. 접사 멈춤 키는 같은 값을 두 번 적어 확실히 멈추게 한다. 렌즈 시야각 30도. 이름표 자리를 위해 `camera.setViewOffset(1920, 1080, 255, 0, 1920, 1080)` 로 제품을 왼쪽으로 옮긴다 | 없음 |
| 접사의 얕은 초점 | 내장 three.js 에 피사계 심도 후처리가 없다 | 기판 접사 두 장면은 AI 일러스트(codex-image)로 바꾼다. 프롬프트에 녹색 회로 기판 접사, 얕은 초점, 따뜻한 주 빛, 칩 윗면 무늬 없음, 글자·로고 없음을 적는다. 받은 그림을 앞(흐린 부품)·가운데(칩)·뒤 세 층으로 나눠 마젠타 바탕에 다시 그려 `scripts/key.py` 로 자르고, 층마다 다른 속도로 옮겨 시차를 낸다(앞 1.4, 가운데 1.0, 뒤 0.7) | 3D 장면에서 그대로 들어가는 연속성. 들어가는 순간을 화면 전체가 기판으로 덮이는 프레임에서 바꿔 감춘다 |
| 사물에 붙는 이름표 | 3D 점과 DOM 글자를 맞춰야 한다 | 층마다 기준점 하나를 두고 `LOOKS.pin(v, cam, 1920, 1080)` 으로 화면 좌표를 얻는다. 점(지름 6px 흰색) → 가는 선(1.5px, rgba(255,255,255,0.45))이 열(가로 1420px)까지 0.25초에 자람 → 글자가 10px 오른쪽에서 미끄러져 들어온다(0.2초). 이름 Pretendard SemiBold 40px, 사양 InterVariable 18px #9A9A9A, 순번 18px #E07858 | 없음 |
| 원근 치수선 | 사물의 원근 위에 눈금을 그려야 한다 | 치수 양 끝의 3D 점 두 개와 수직 눈금 끝점을 `LOOKS.pin` 으로 화면에 옮겨 SVG 선(1.5px, #B13018)으로 그린다. 선은 0.4초에 길이 방향으로 자라고 숫자는 선의 기울기 각도로 회전한 InterVariable 22px. 숫자는 사용자가 준 사양에서 확인한 값만 | 없음 |
| 기판 위 흰 조명 소자가 켜지기 | 빛이 기판 구멍으로 새는 효과 | 소자 윗면 재질의 자체 발광을 0 → 2.0 으로 0.3초에 올리고 bloom 이 잡게 한다. 기판 구멍 위치에 작은 빛 점(`LOOKS.orbs`, 크기 작게)을 같은 시각에 켠다 | 구멍을 통과하는 빛의 모양 |
