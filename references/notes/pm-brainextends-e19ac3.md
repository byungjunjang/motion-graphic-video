# 검은 무대 속 음악 앱 · 앨범 한 장이 끝까지 가는 제품 영상 — 분석 노트

> 녹색 빛이 번진 바탕 위에 모서리가 둥근 거의 검은 무대(화면의 80x76%)를 놓고, 그 안에서 음악 앱 화면이 약 1초마다 바뀌는 18초 제품 영상. 로고 → 두 줄 문구 → 앱 화면 → 추천 카드 → 곡 목록 → 재생목록 띠 → 검색 → 앨범 상세 → 녹색 전면 → 앨범 확대 → 문구 → 재생목록 표지 → 표지들이 모여 로고 → 끝 로고 순서다. 무지갯빛 앨범 표지 한 장이 검색·상세·확대·모이기를 거치며 끝까지 같은 물체로 이어지고, 아래의 가는 재생 막대가 장면들을 묶는다. 앱·구독 서비스·디지털 제품 소개에 맞는다. 제품 광고 · 화면 속 화면 · 1초 단위 편집.

출처 · pm:brainextends-e19ac3. 작성자의 프롬프트는 약 8천 자로 길다. 주제(실존 음악 서비스의 제품 영상), 스타일(무대 크기, 바탕 색 방향, 글 색, 강조색, 글꼴 계열, 앨범 그림 재료), 구성(0.6~1.5초 단위 장면표 17칸, 재생 막대, 움직임 원칙, 소리, 검증 방법)을 모두 정했다. 실제 요소의 px 크기와 점유율, 실제 색 값, 움직임이 멈추는 구간, 원래 글과 실제 화면이 다른 점은 비어 있다. 이 노트는 영상 프레임(0.5초 간격 시트 2장 37칸)과 원본 해상도 프레임 10장을 보고 그 빈칸만 채웠다. 장면 순서는 원래 글과 거의 같으므로 시간표는 실제 값만 적는다.
측정 · 파일 1920x1080 · 30fps · 18.1초. 원래 글은 60fps 로 정했지만 파일은 30fps 다. 장면 감지가 잡은 하드 컷은 0번이다. 0.5초마다 움직임 세기의 평균은 5.9 다. 가장 큰 값은 8.0초(29.4, 녹색 전면 → 검은 무대), 7.5초(23.2), 9.5초(21.2), 8.5초(16.3)다. 세기가 0 인 정지는 10.0~10.5초(1.0초)와 15.5~18.0초(2.5초, 끝 로고)다. 색 값은 원본 프레임에서 9x9 칸 중앙값으로 잰 근삿값이다.
소리 · 듣지 못했다. 측정값만 적는다. 측정 BPM 은 79.5(마디 3.04초)다. 원래 글은 약 120 BPM 으로 정했다. 큰 타격이 0.87, 2.39, 3.90, 5.42, 6.94, 8.46초로 1.52초 간격이다. 1.52초는 79 BPM 의 2박이고, 118 BPM 의 3박이기도 하다. 타격 사이의 작은 타격은 약 0.19초 간격이다. 이것만으로는 어느 쪽인지 정할 수 없다. 큰 타격과 겹치는 화면 사건은 두 줄 문구 등장(0.87초), 앨범이 왼쪽으로 미끄러짐(6.94초), 녹색 전면에서 검은 무대로 돌아옴(8.46초), 재생목록 표지 등장(11.51초), 끝 로고 문구(16.06초)다. 음량은 거의 고르다(-11~-16dB). -19dB 아래 무음은 7곳이고 마지막 17.32~18.06초가 가장 길다.

## 3. 움직임

- 장면 하나가 0.6~1.5초다. 대부분 약 1초다. 장면마다 움직임 세기가 한 번 올랐다가 내려온다(예 · 2.0초 10.5 → 3.0초 1.0 → 3.5초 8.7 → 5.0초 0.8). 빠르게 바뀌고 잠깐 멈추는 박자가 고르다.
- 들어오기 · 아래에서 위로 짧게(20~40px) 올라오며 흐림 → 선명. 글은 가려진 틀 안에서 위로 올라오는 등장이다.
- 앱 화면은 1.5초에 조금 기울어진 채 흐리게 들어와 2.0초에 정면으로 선다.
- 앨범은 위치를 이어 간다. 결과 줄 → 가운데 → 왼쪽 → 작은 타일 → 큰 확대로 갈 때 한 프레임도 끊기지 않는다.
- 녹색 전면은 무대 안만 녹색으로 덮는다. 무대 밖 바탕은 그대로다.
- 확대(8.5~9.5초)는 가장 빠른 움직임이다(세기 16~29). 원래 글은 이 구간에 짧은 움직임 흐림을 정했다.
- 표지 넷이 모일 때 회전과 겹침 순서가 같이 바뀐다. 마구 떠다니지 않고 함께 움직인다.
- 끝 로고는 2.5초 동안 완전히 멈춘다.

## 4. 전환

- 컷이 없다. 모든 전환이 무대 안 요소의 변형이다.
  - 로고 → 문구 · 로고가 작아져 위로 가고 그 자리에 문구가 올라온다.
  - 카드 → 목록 · 카드가 줄어 목록 줄의 썸네일이 된다.
  - 검색 결과 → 앨범 상세 · 썸네일이 커져 가운데 표지가 된다(위치 이어 가기).
  - 상세 → 녹색 · 무대 안이 녹색으로 덮이고 표지가 작아진다(0.5초).
  - 녹색 → 확대 · 검은 무대로 돌아오며 표지가 무대보다 크게 커진다.
  - 확대 → 문구 · 표지가 걷히고 문구가 남는다.
  - 표지 넷 → 로고 · 표지들이 가운데로 모이며 로고가 그 자리에서 나온다.
- 나가는 글이 사라진 뒤에 들어오는 글이 같은 자리에 온다. 두 글이 겹치는 프레임이 없다.
- 재생 막대가 2.4~7.5초와 8.5~14.5초에 그대로 있어 화면이 바뀌어도 같은 앱 안이라는 느낌을 준다.

## 5. 타이포

- 글꼴은 고딕 계열 하나다. 굵기는 보통과 굵게 두 가지다.
- 크기 단계 · 재생 막대·목록 글자 약 1%, 작은 보조 줄 약 1.5%, 카드 위 제목 약 2%, 두 줄 문구 약 4.5%(줄 높이 약 50px), 끝 로고의 글자 이름 약 6%.
- 두 줄 문구는 두 번 나온다(1.0초, 10.5초). 첫 줄 흰색 보통 굵기, 둘째 줄 녹색 굵게. 가운데 정렬. 폭은 화면의 14~16% 뿐이다.
- 재생목록 표지에는 굵은 대문자 표지 글자가 왼쪽 위에 있다. 표지 디자인의 일부다.
- 끝 화면 · 로고 아이콘 + 글자 이름이 한 줄, 그 아래 작은 두 줄(흰색 + 녹색).

## 6. 가져올 것

- 12초 판에서 꼭 남길 대표 장면 · 원본 5.5~9.5초. 검은 무대(화면의 80x76%, 모서리 50px) 안에서 앨범 표지 한 장이 검색 결과의 40px 썸네일 → 381px 가운데 표지 → 왼쪽으로 미끄러지며 오른쪽에 곡 정보 → 무대 안 녹색 전면 위 250px 타일 → 무대 위 가장자리에서 잘리는 850px 확대로 이어진다. 아래 943x73px 재생 막대가 녹색 전면 때만 빠진다. 표지가 매번 새 그림으로 바뀌거나 무대 밖으로 나가면 이 영상이 아니다.
- 12초 판 압축 예 · 0~0.5초 로고가 커진다. 0.5~1.3초 두 줄 문구. 1.3~2.3초 앱 화면 + 추천 카드. 2.3~3.1초 재생목록 띠. 3.1~3.9초 검색 + 결과. 3.9~6.5초 대표 장면(상세 0.6, 왼쪽 0.6, 녹색 0.6, 확대 0.8초). 6.5~7.5초 두 줄 문구. 7.5~9.0초 표지 넷이 모여 로고. 9.0~12.0초 끝 로고 정지. 곡 목록과 재생목록 3장 → 6장은 뺀다.
- 무대 위 무대 구도. 바탕은 색과 빛만, 내용은 둥근 무대 안에만 둔다. 무대가 화면을 정리해 준다.
- 주인공 그림 한 장이 모든 장면을 지나가는 구성.
- 장면을 이어 주는 가는 막대(여기서는 재생 막대). 대상 앱의 늘 보이는 요소(입력창, 탭 막대)를 같은 자리에 둔다.
- 약 1초 장면 + 짧은 멈춤의 고른 박자.
- 브랜드 색으로 무대 안을 한 번 덮는 0.8초 쉼표.

## 7. 함정

- 화면의 로고 아이콘, 글자 이름, 두 줄 문구, 재생목록 이름, 곡 이름, 가수 이름은 실존 서비스와 원작의 것이다. 쓰지 말고 옮기지 않는다. 역할(서비스 로고, 두 줄 구호, 재생목록 이름, 가상 곡 이름)만 가져온다. 실존 서비스의 로고와 화면을 흉내 내어 그리지 않는다.
- 오른쪽 위 제작자 표기는 원작의 것이다. 넣지 않는다.
- 글이 아주 작다(1~4.5%). 휴대전화 화면에서는 재생 막대와 목록 글자가 읽히지 않는다. 한국어 판에서는 두 줄 문구를 60~72px, 보조 줄을 26px 아래로 내리지 않는다.
- 앨범 그림이 영상의 질을 정한다. 단색 사각형으로 바꾸면 확대 장면이 비어 보인다. 확대할 그림은 1024px 이상으로 만든다.
- 장면 17개를 18초에 넣으면 장면 하나가 1초 안팎이다. 12초 판에서 장면을 그대로 두면 0.7초가 되어 글을 읽을 수 없다. 장면 수를 9~10개로 줄인다.
- 원래 글은 60fps 와 부프레임 3~5장 합성을 정했지만 파일은 30fps 다. 확대 구간만 움직임 흐림을 쓰고 나머지는 선명하게 둔다.
- 끝 로고 2.5초 정지는 18초 판에서는 괜찮지만 12초 판에서는 3초를 넘기지 않는다.

## 8. 코드로 재현 못 하는 요소와 대체 방법

글꼴은 Pretendard Regular·SemiBold 와 InterVariable 이다. 값은 1920x1080 기준이다.

| 요소 | 왜 어려운가 | 대체 방법(구체 값) | 대체하면 잃는 것 |
|---|---|---|---|
| 무지갯빛 액체 비단 앨범 | 사실적인 반사와 주름 | AI 일러스트(codex-image)로 정사각 1024px 를 그린다. 연보라·하늘·분홍·금빛 액체 비단, S자 주름, 글자·로고 없음. 또는 three.js 에서 `LOOKS.liquidMetal` 을 쓰고 `LOOKS.env(gl, 'dome')` 환경맵을 비춰 canvas 로 굽는다 | 그림 한 장의 세밀한 결(three.js 판은 무지갯빛이 약하다) |
| 둥근 검은 무대 + 녹색 바탕 | 없다. CSS 로 된다 | 무대 div `left:190px; top:168px; width:1540px; height:822px; border-radius:50px; background:#0B0C0F; overflow:hidden`. 바탕 `radial-gradient(circle at 0% 0%, #20B54E, #0A4A2D 35%, #04170E 60%, #000501 90%)` | 없음 |
| 앱 화면들 | 실존 앱 화면이다 | DOM 으로 가상 음악 앱을 짓는다. 옆 메뉴 폭 140px, 표지 카드 165px, 목록 줄 40px, 재생 막대 943x73px #222C26 + 1px 테두리 rgba(255,255,255,.08) | 없음 |
| 재생목록 표지 6장 | 그래픽 디자인 표지 | DOM 으로 단색 바탕(#F2C230, #E95A9A, #3D6FE0, #DDE5DA, #7B4BD6, #E8572F) + 큰 원·줄무늬 도형 하나 + Pretendard SemiBold 28px 이름 두 줄 | 표지마다 다른 손맛 |
| 앨범 위치 이어 가기 | 레이아웃 사이 보간 | 표지 하나를 무대 안 절대 위치로 두고, 장면마다 목표 사각형(40 → 381 → 250 → 850px)을 표로 적어 0.5초씩 `left/top/width` 를 보간한다. 곡선 `cubic-bezier(.22,1,.36,1)` | 없음 |
| 확대 구간 움직임 흐림 | 부프레임 합성 | 확대 0.5초 동안만 표지 복사본 3장을 각각 이전 0.011·0.022·0.033초의 크기로 그리고 `opacity` .25 로 겹친다 | 진짜 셔터 흐림의 매끄러움 |
| 표지 넷이 모여 로고 | 3D 회전과 겹침 | CSS `perspective: 1200px` 안에서 표지마다 `rotateY` ±12°, `rotateZ` ±6° 를 주고 0.8초 동안 가운데로 모은다. `z-index` 를 t 로 바꾼다. 가운데에서 가상 로고(원 지름 160px, 강조색)가 `scale` 0 → 1 | 없음 |
| 로고 아이콘 | 실존 로고다 | 대상 서비스의 허락받은 로고 파일만 쓴다. 없으면 강조색 원 + 기호 하나로 가상 로고를 만든다 | 없음 |
