# 밤 마을을 깨우는 픽셀 마법사 · 한 판짜리 놀이 화면 — 분석 노트

> 짙은 보라 밤하늘 아래, 지팡이를 든 동그란 올빼미 모양 마법사가 주문을 네 번 쏘아 잠든 집 네 채의 창에 불을 켜는 18.8초 픽셀 그림 영상. 집이 모두 깨면 달이 떠오르고, 길게 모은 큰 주문이 달에 맞아 달이 웃는 해로 바뀐다. 끝에 금빛 완료 문구 한 줄과 별 세 개가 뜨고 화면이 어두워진다. 논리 해상도 128칸짜리 그림을 정수배로 키워 화소가 또렷하다. 게임·앱의 한 단계 완료, 작은 목표를 하나씩 채워 큰 보상을 받는 서비스 소개에 맞는다. 16비트 픽셀 그림 · 놀이 화면 · 귀여운 마법.

출처 · gh:zacxbt-944604. 원래 글은 약 2,200자의 구현 명세다. 그리기 규칙(논리 해상도, 정수배 확대, 반올림 좌표, 고정 색표 약 24색), 인물 구성, 네 상태(대기 · 모으기 · 쏘기 · 돌아오기)의 반복, 입자 풀, 배경 요소(별, 달, 돌 바닥선), 테두리 빛을 정했다. 화면 배치, 크기, 장의 시각, 놀이 목표, 글자는 정하지 않았다. 실제 영상은 원래 글과 많이 다르다(아래 `## 1`). 이 노트는 영상 프레임(0.5초 간격 시트 38칸, 대표 구간은 0.1~0.2초 간격으로 직접 뽑은 24장)을 보고 썼다.

## 3. 움직임

- 모든 좌표가 10px 칸에 맞는다. 몸, 지팡이, 불꽃, 궤적 점, 글자가 칸 사이에 서지 않는다.
- 마법사의 동작은 초당 8~12장처럼 끊어 보인다(원래 글대로). 몸통 흔들림은 1칸, 지팡이 들기는 약 30° 다.
- 한 번의 주문은 약 2.5초 주기다. 모으기 약 0.8초 → 쏘기 1장(번쩍임 + 흔들림) → 날아감 약 0.5초 → 맞음과 보상 약 0.6초 → 쉼.
- 주문 궤적은 포물선이다. 작은 주문은 높이 약 120px, 큰 주문은 약 450px 를 오른다. 궤적은 점 꼬리를 남기고, 점은 색표 순서(흰색 → 민트 → 짙은 보라)로 어두워지며 사라진다.
- 모으기 불꽃은 지팡이 구슬을 나선으로 돌며 안으로 감겨 든다. 큰 모으기에는 점선 원 하나가 더 돈다.
- 쏘기와 맞음에는 세 가지가 함께 일어난다. 화면 전체 색이 한 단 밝아진다, 화면이 1~2칸 흔들린다, 십자 별이 뜬다. 셋 다 1~3장(0.02~0.05초)만 이어진다.
- 보상은 아래에서 위로 떠오른다. 인사말, 셈 아이콘의 반짝임, 별 점수.
- 집이 깨는 순서는 왼쪽에서 오른쪽이다. 주문이 가까운 집부터 닿아 궤적 길이가 점점 길어진다(약 250px → 600px). 그래서 같은 주기여도 뒤로 갈수록 날아가는 시간이 조금 길어 보인다. 잠든 표시는 창이 켜지는 장에 함께 사라진다.
- 카메라는 움직이지 않는다. 화면 안 움직임은 주인공 둘레와 집 위, 하늘의 작은 구역에만 있다. 평균 세기 2.7 이 낮은 이유다.

## 4. 전환

- 장면 전환이 없다. 한 화면 고정이고 장은 놀이 진행(셈 0 → 4, 달, 해, 완료)으로 나뉜다.
- 쏘기·맞음의 번쩍임은 흰 화면이 아니다. 색표 전체를 한 단 위 색으로 바꾸는 번쩍임이다. 흰색으로 덮이는 프레임이 없다.
- 달 → 해 · 맞는 순간 같은 자리에서 한 장에 바뀐다. 바뀐 뒤 별 폭발과 빛 고리가 덮어 준다.
- 정보 줄 → 완료 띠 · 글자를 지우고 한 장에 바꾼다.
- 끝은 0.6초 어두워짐이다. 원래 글의 끊김 없는 반복이 아니다.

## 5. 타이포

- 글자는 모두 화소 글꼴이다. 한 글자 높이 5칸(50px, 화면 높이의 5%), 획 굵기 1칸이다.
- 정보 줄 · 왼쪽(가로 3~21%)에 단계 이름 + 숫자, 오른쪽(가로 82~97%)에 집 아이콘 + 셈. 세로 87~92%. 색은 짙은 보라 회색(#403557)이고 숫자만 연보라(#8f83bc)로 밝다. 맞는 순간과 완료 때 민트·금빛으로 바뀐다.
- 안내 줄 · 정보 줄 아래 가운데(세로 93~98%) 한 줄. 같은 크기. 깜박인다.
- 완료 띠 · 가운데 정렬 한 줄, 금빛. 아래에 별 세 개(각 약 40px).
- 인사말 · 집 위 떠오르는 두 글자, 높이 약 3칸(30px). 둘째부터 곱하기 숫자가 붙는다.
- 화면의 글자(단계 이름, 안내, 인사말, 완료 띠)는 옮기지 않는다. 역할만 가져온다.

## 6. 가져올 것

- 12초 판에서 꼭 남길 대표 장면 · 10.0~11.8초. 화면 왼쪽 아래 마법사(18%x24%)가 점선 원을 돌리며 큰 주문을 모으고, 민트 십자 별과 함께 쏜다. 주문이 높이 약 450px 의 포물선으로 오른쪽 위 달(지름 130px)에 맞고, 화면 색이 한 단 밝아지며 2칸 흔들리고, 달이 웃는 금빛 해로 바뀐다. 동시에 보이는 요소는 마법사, 지팡이, 집 넷, 달(해), 궤적, 별 6~8개, 정보 줄 둘로 약 16개다. 칸에 맞는 또렷한 화소와 달이 해가 되는 순간이 없으면 이 영상이 아니다.
- 12초 판 압축 예 · 0~1.0초 첫 주문과 첫 집. 1.0~4.0초 둘째·셋째·넷째 집을 1초씩(모으기를 0.3초로 줄인다). 4.0~5.5초 달이 떠오르고 안내 줄. 5.5~7.3초 큰 모으기와 쏘기, 맞음(대표 장면). 7.3~8.5초 마을 인사와 불꽃 둘. 8.5~11.4초 완료 띠와 별 셋. 11.4~12초 어두워짐. 불꽃놀이의 나머지와 대기 흔들림을 뺀다.
- 작은 목표 넷 → 큰 보상 하나의 구성. 셈 0 → 4 가 화면 구석에 늘 보여 진행을 알린다. 대상의 기능 네 가지를 "깨우는 집"으로 둘 수 있다.
- 흰 화면 대신 색표를 한 단 밝히는 번쩍임. 눈이 덜 아프고 픽셀 그림의 결을 지킨다.
- 쏘기 한 장에 번쩍임 + 흔들림 + 십자 별을 함께 거는 타격감.
- 칸 단위 디더 띠로 그라데이션 없이 하늘의 깊이를 내는 방법.

## 7. 함정

- 화면의 글자는 옮기지 않는다. 인물·달·해의 얼굴은 이 영상의 디자인이다. 그대로 베끼지 말고 대상의 마스코트로 새로 그린다.
- 원래 글만 따르면 뾰족 모자 노인이 나온다. 실제 영상의 매력은 둥근 몸, 큰 눈, 놀이 목표다. 레퍼런스로 쓸 때는 영상 쪽을 따른다.
- 칸을 지키지 않으면 바로 깨진다. canvas 에 `imageSmoothingEnabled = false`, CSS 에 `image-rendering: pixelated` 를 주고, 그리는 좌표는 모두 `Math.round` 한다. 번짐 효과(`shadowBlur`, 그라데이션)를 쓰지 않는다.
- 소리가 없다. 우리 영상에서는 쏘기·맞음·집 깸에 효과음을 붙여야 타격감이 산다(synth.py 효과음, 또는 승인 뒤 소리 생성 단계).
- 움직임 세기 평균이 2.7 로 낮다. 화면이 작게 움직여서 12초 판에서는 심심할 수 있다. 주문 주기를 2.5초에서 1초로 줄인다.
- 정사각에 가까운 화면(1280x1008, 1.27:1)을 16:9(1920x1080)로 옮기는 구도.
  - 칸 크기 10px 를 그대로 두고 논리 해상도를 128x101 → 192x108 로 넓힌다.
  - 가로로 늘어난 64칸은 양옆에 32칸씩 나눈다. 하늘 띠와 디더 줄, 땅, 바닥선은 폭 1920px 로 그냥 이어 그린다.
  - 세로로 늘어난 7칸은 위 하늘에 4칸, 정보 줄 아래에 3칸을 더한다. 띠 경계는 세로 0~31%, 33~55%, 57~74%, 땅 74~82%, 바닥선 82%, 정보 줄 85~100% 로 다시 맞춘다.
  - 마법사는 가로 31~43%(논리 x 61~84)로 옮긴다. 크기는 230x245px 그대로다(화면 폭의 12%, 높이의 23%).
  - 집은 네 채 → 여섯 채로 늘리고 가로 52~95% 에 둔다(각 110px, 간격 40px). 목표 셈도 6 으로 바꾼다.
  - 달은 가로 74~81%, 세로 12~24% 에 둔다. 큰 주문 포물선의 가로 길이가 약 720px → 1000px 로 길어지니 날아가는 시간을 0.4초 → 0.55초로 늘린다.
  - 정보 줄 왼쪽 글자는 왼쪽에서 60px, 오른쪽 셈은 오른쪽에서 60px 에 둔다.
- 한국어 글자를 화소 글꼴로 만들 수 없다. 정보 줄과 완료 띠는 Pretendard SemiBold 를 작은 크기로 그려 칸 격자에 다시 찍거나(`## 8`), 숫자와 아이콘만 남긴다.

## 8. 코드로 재현 못 하는 요소와 대체 방법

값은 1280x1008, 칸 10px 기준이다. 이 영상은 원래 canvas 2D 로 만든 것이라 대부분 그대로 재현된다.

| 요소 | 왜 어려운가 | 대체 방법(구체 값) | 대체하면 잃는 것 |
|---|---|---|---|
| 화소 인물과 표정 | 손으로 찍은 칸 그림 | 원래 글대로 사각형과 칸 줄로 23x25칸 인물을 그린다. 몸 #bd9555, 그늘 한 단 짙게, 외곽선 #2f241f, 눈 반사 #5ff5b9, 볼 #da7170. 표정은 눈 모양 3장(뜸·감음·웃음)만 바꾼다 | 없음 |
| 화소 글꼴 | 화소 글꼴 파일이 없다 | 숫자·라틴은 3x5칸 글자표를 코드로 정의해 칸으로 찍는다. 한국어는 Pretendard SemiBold 를 화면 밖 canvas 에 높이 7칸(70px)으로 그린 뒤 10px 칸마다 가운데 화소를 읽어 50% 넘으면 칸을 칠한다 | 한국어 글자 모양이 거칠어진다 |
| 색표 한 단 밝히는 번쩍임 | 없다. 색표로 된다 | 24색 표를 밝기 순으로 두고, 쏘기·맞음 장에서 모든 화소의 색 번호에 +1 을 더해 그린다(1~3장) | 없음 |
| 화면 흔들림 | 없다 | 쏘기 때 1칸, 맞음 때 2칸 만큼 전체 그림을 옮겨 그린다. 빈 가장자리는 #07030e 로 칠한다 | 없음 |
| 디더 띠 | 없다 | 띠 경계마다 높이 2칸 줄에 두 색을 바둑판으로 번갈아 찍는다 | 없음 |
| 주문 궤적 꼬리 | 없다 | 입자 풀(원래 글대로 미리 잡은 배열) 200개. 점마다 수명 0.5초, 색 번호를 흰색 → 민트 → 짙은 보라로 3단 내린다. 위치는 `Math.round(x / 10) * 10` | 없음 |
| 영상 렌더 | 실시간 루프와 seek(t) 차이 | 원래 글의 고정 60hz 갱신 루프 대신, 시각 t 에서 상태를 계산하는 함수로 바꾼다. 입자도 t 와 씨앗으로 위치를 계산한다(`HAND.rngKey` 로 씨앗별 난수) | 실시간 조작 |
