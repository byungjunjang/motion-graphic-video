# 흰 바탕 UI 한 장 · 카메라 하나로 훑는 웹 화면 홍보 — 분석 노트

> 거의 흰 따뜻한 회백색 바탕의 웹 화면 전체를 한 장의 큰 판으로 놓고, 카메라 하나가 물러나기·흐르기·빨려 들어가기·다가가기만으로 장면을 잇는 화면 녹화형 홍보 문법. 빠른 이동은 0.5초 안에 끝나고 그 사이 2~4초를 버틴다. 타일이 꽉 찬 화면이 될 때 모서리 둥글기가 0 이 되어 같은 물체로 이어지고, 꽉 찬 화면에서는 박마다 하드 컷이 지나간다. 강조색은 붉은 주황 하나를 세 곳에만 쓴다. 뒤로 갈수록 시선을 격자 전체에서 작은 요소 하나로 좁힌다. 웹 서비스·앱·포트폴리오 사이트 소개에 맞는다.

출처 · pm:antonio-kodheli-490109. 작성자의 프롬프트는 약 4천 자다. 주제, 스타일(거의 흰 바탕, 검은 알약, UI 글꼴 하나 + 고정폭 글꼴, 강조색 하나와 그 쓰임 세 곳), 구성(박 단위 장면표 9칸), 제작 방법과 금지 목록을 정했다. 실제 요소의 크기·위치·점유율, 타격과 화면 사건의 대응, 끝 화면의 배치 숫자는 비어 있다. 이 노트는 영상 프레임(1초 간격 시트 2장, 0.5초 간격으로 직접 뽑은 46장)을 보고 그 빈칸을 채웠고, 원래 글과 실제 화면이 다른 점을 적었다.
측정 · 파일 1280x720 · 30fps · 23.1초. 아래 크기는 1920x1080 으로 환산했다(1.5배). 장면 감지가 잡은 하드 컷은 2곳(6.97, 7.47초 · 30.2%, 32.3%)이다. 타일 → 꽉 찬 화면은 카메라가 빨려 들어간 것이라 컷으로 잡히지 않았다. 0.5초마다 움직임 세기의 평균은 14.1 이다. 가장 큰 값은 0.0초(65.6, 물러나기), 8.0초(56.8, 타일로 줄어들기), 6.5초(56.1), 6.0초(41.1), 4.5초(43.1)다. 11.0~16.0초 평균은 약 4.6, 18~23초는 4.9~5.9 로 고르다(타일 줄이 계속 흐른다). 색 값은 원본 프레임에서 잰 근삿값이다.
소리 · 듣지 못했다. 측정값만 적는다. BPM 120.2(박 0.5초, 마디 2.0초). 0.25초 간격으로 고른 타격이 처음부터 끝까지 이어진다. 킥(120Hz 아래 비율이 큰 타격)은 9.08초(39.3%)부터 거의 매 박 들어온다. 그 전에는 1.59초 한 번뿐이다. 음량(rms)은 0~7초 -13~-16dB 에서 7.5초(32.5%) 뒤 -11~-13dB 로 오른다. 가장 센 타격은 18.05(1.00), 12.06(0.94), 20.05(0.94), 19.05(0.88), 10.07(0.85)초다. 원래 글은 음악의 떨어짐(드롭)을 버스트에 맞추라고 정했다. 실제 측정으로는 드롭이 버스트보다 1~2.5초 늦다고 본다. 두 하드 컷(6.97, 7.47초)은 타격(7.08, 7.57초)보다 약 0.1초 앞선다. -28dB 아래 짧은 무음 11곳이 마디 끝(3.26, 5.28, 11.30, 13.78, 19.28, 21.28초 등)에 0.25초씩 있다.

쓰는 법 · 이 노트는 스타일 문법(색·질감·크기 비율·움직임·전환·타이포·밀도)만 적는다. 원본의 소재·장면·순서는 적지 않았다. 숫자는 원본 영상을 보고 잰 근삿값이다.

## 1. 본질

- 바탕은 거의 흰 따뜻한 회백색(#F6F6F3 근처)이다. 끝 화면은 #F5F5F2 근처로 같다. 그림자와 그라데이션이 없다.
- 화면에 나오는 것은 서비스 화면의 UI 요소뿐이다. 머리글(서비스 이름 + 한 줄 소개 + 작은 메뉴), 세 칸 격자의 움직이는 타일, 타일 아래 작은 표기 줄, 상세 화면(왼쪽 큰 칸, 오른쪽 표기 줄·제목·정보 세 줄·글 상자), 검은 알약 버튼.
- 강조색은 붉은 주황 하나다. 실제로 잰 형광펜 색은 #DB3530 근처다(원래 글의 값보다 조금 어둡고 붉다). 형광펜, 커서 둘레 빛, 알약의 점에만 쓴다.
- 색이 강한 것은 타일 안의 장면들이다. 빨강(#EB4A3A 근처), 연두(#C5FF26 근처), 파랑(#2F2CEF 근처), 빨강(#E44031 근처). 흰 바탕 UI 와 강한 단색 화면이 번갈아 나온다. 꽉 찬 단색 화면은 단색 바탕 + 검은 큰 글자 한 낱말(폭 85%, 높이 36%) 구도다.
- 카메라는 하나다. 화면 전체를 한 장의 큰 판으로 놓고 그 위를 움직인다. 한 번에 한 가지 이동만 한다.
- 크기(1920 기준).
  - 격자 · 칸 폭 552px(화면 폭의 29%), 간격 36px. 타일은 16:9, 모서리 12px. 격자 화면에 타일 9개 안팎이 동시에 보인다.
  - 다가간 상세 화면 · 제목 한 줄(화면 높이의 약 3%)이 세로 33% 지점, 글 상자가 가로 7~45%, 세로 40~62% 에 고정폭 글 8줄.
  - 형광펜 띠 · 약 415x41px, 가로 46~68%, 세로 47.5~51%.
  - 커서 둘레 빛 · 지름 약 30px.
- 아닌 것 · 유리 카드, 그라데이션, 튀는 글자, 모든 것에 쓰는 흐려짐, 서비스에 없는 버튼이나 숫자.

## 3. 움직임

- 카메라 이동이 전부다. 이동은 네 종류다. 물러나기, 흐르기, 빨려 들어가기, 다가가기. 버티는 동안에도 카메라가 아주 조금 다가간다(멈춘 화면이 없다).
- 빠른 이동은 0.5초 안에 끝난다. 이동 사이의 버티기는 2~4초다. 빠름 → 버팀 → 빠름의 박자다. 원래 글은 첫 물러나기를 2박(1.0초)으로 정했지만 실제로는 0.5초 안에 끝난다.
- 타일 안의 장면은 계속 돈다. 격자 화면에서 9개 안팎의 작은 장면이 동시에 움직인다. 이웃 타일이 같은 프레임에 바뀌지 않는다.
- 커서는 하나다. 둘레에 붉은 주황 빛 원이 있다. 누를 때 원이 조금 줄었다 커진다.
- 형광펜은 왼쪽에서 오른쪽으로 0.3~0.5초에 칠해진다. 띠는 단색이고 가장자리가 반듯하다. 칠해진 부분 글자는 흰색으로 뒤집힌다.
- 버튼은 누른 뒤 0.5초에 검은 알약 + 체크 표시로 바뀌고, 다음 박에 화면이 나간다.
- 끝 화면의 오른쪽 타일 줄은 5초 동안 같은 속도로 위로 흐른다(움직임 세기 약 5 로 고르다).
- 움직임 세기의 모양 · 큰 봉우리(40~66)가 0~2.2%, 19.5~28.1%, 34.6% 에 몰려 있고 47.6~69.3% 는 낮다(1.3~11.3). 앞 절반은 카메라가 바쁘고 뒤 절반은 커서·형광펜 같은 작은 사건만 움직인다. 화면 점유율로 보면 앞 절반의 주인공은 격자 전체(화면의 약 90%)이고, 뒤 절반의 주인공은 글 상자(약 38x22%)와 알약 하나(약 20x6%)다. 점점 작은 것으로 시선을 좁힌다.

## 4. 전환

- 컷 대신 카메라가 장면을 잇는다. 꽉 찬 화면 → 격자는 물러나기, 격자 → 꽉 찬 화면은 빨려 들어가기, 꽉 찬 화면 → 격자는 줄어들기(일치 컷), 격자 → 상세는 타일이 피어나기, 상세 → 끝은 왼쪽으로 밀기.
- 타일이 꽉 찬 화면이 될 때 모서리 둥글기가 0 이 된다. 반대로 줄어들 때 둥글기가 돌아온다. 그래서 타일과 꽉 찬 화면이 같은 물체로 보인다.
- 하드 컷은 버스트의 2번뿐이다. 꽉 찬 화면 세 개를 박마다 바꾼다.
- 버튼 알약 → 끝 화면 알약 · 버튼 하나가 글자만 바꿔 끝 화면 요소가 된다. 상세 화면의 요소가 끝 화면으로 넘어간다.

## 5. 타이포

- 글꼴은 고딕 계열 UI 글꼴 하나와 고정폭 글꼴 하나다. 고정폭은 글 상자에만 쓴다.
- 서비스 이름 · 굵은 고딕, 검정(#1A1A1A 근처). 격자 화면에서 가로 5% 에서 시작해 높이 약 7%(대문자 기준), 세로 13~23% 지점이다. 끝 화면에서는 폭 40%, 세로 32~45% 지점으로 더 크다.
- 한 줄 소개 · 보통 굵기, 회색, 화면 높이의 약 2%. 끝 화면에서 두 줄이다.
- 타일 아래 표기 · 동그란 사진 + 작은 글자(높이 약 1%). 모든 타일에 붙어 있다.
- 글 상자 글 · 고정폭, 회색, 줄간격 약 1.6, 글자 높이 약 1.5%(1.5배 다가간 뒤 약 2%).
- 알약 · 검은 바탕에 흰 글자, 높이 약 6%, 왼쪽에 붉은 주황 점 하나.

## 6. 가져올 것

- 핵심 장치 · 서비스 화면 전체를 한 장의 큰 판으로 놓고 카메라 하나로만 움직인다. 빠른 이동은 0.5초 안에 끝나고 그 사이 2~4초를 버티며, 버티는 동안에도 아주 조금 다가간다.
- 핵심 장치 · 격자 타일(552px, 모서리 12px)이 꽉 찬 화면이 될 때 둥글기가 0 으로 줄고, 줄어들 때 돌아온다. 타일과 꽉 찬 화면이 같은 물체로 이어진다.
- 핵심 장치 · 꽉 찬 단색 화면(단색 바탕 + 큰 글자 한 낱말)을 박마다(0.5초) 하드 컷으로 세 번 바꾸고, 컷은 타격보다 약 0.1초 앞에 둔다.
- 핵심 장치 · 넓게 → 좁게 점유율을 줄여 간다. 화면의 약 90% 인 격자에서 약 38x22% 상자, 약 20x6% 알약 하나로. 앞 절반은 카메라가 바쁘고 뒤 절반은 작은 사건만 움직인다.
- 강조색을 형광펜·커서·점 세 곳에만 쓰는 절제.
- 앞 화면의 작은 요소 하나가 글자만 바꿔 끝 화면 요소가 되는 마무리. 대상 서비스의 핵심 기능 하나를 가장 좁힌 자리에 둘 수 있다.

## 7. 함정

- 원본 화면의 실존 로고·이름은 쓰지 않는다.
- 타일 안 장면 9개를 동시에 돌리면 렌더가 무겁다. 각 타일을 canvas 나 DOM 의 짧은 반복 움직임으로 만들고, 시작 위상을 0.13초씩 어긋나게 한다.
- 흰 바탕과 같은 색의 타일은 사라진다. 타일마다 1px 테두리(#E4E4E0 근처)를 준다.
- 카메라가 다가간 뒤 머리글이나 정보 줄이 화면 가장자리에 걸린다. 다가간 마지막 프레임을 꼭 확인한다.
- 한국어로 옮기면 서비스 이름과 소개가 한글이 된다. 끝 화면 이름은 Pretendard SemiBold 120~130px, 소개는 Regular 34px 두 줄로 둔다. 글 상자는 한국어 글이면 고정폭 대신 Pretendard Regular 26px, 숫자·라틴만 InterVariable 을 쓴다.
- 드롭을 버스트에 맞추라는 것이 원래 의도였지만 실제 영상은 1~2.5초 어긋났다. 우리 판에서는 버스트 첫 컷을 마디 첫 박에 두고 `audio-probe --fit` 으로 오차를 잰다.

## 8. 코드로 재현 못 하는 요소와 대체 방법

글꼴은 Pretendard Regular·SemiBold 와 InterVariable 이다. 값은 1920x1080 기준이다.
