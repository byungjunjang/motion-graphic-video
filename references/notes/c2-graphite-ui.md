# 흑연색 앱 화면 · 누르면 줄이 지워지는 할 일 목록 — 분석 노트

> 짙은 흑연색 바탕에 앱 창 하나가 3D 로 기울어 놓인 12초 영상. 창이 평평하게 다가오고, 초록 커서가 초록 단추 하나를 누르면 목록의 줄이 위에서부터 차례로 체크되고 그어진다. 창이 오른쪽으로 돌아 비켜서며 왼쪽에 큰 제목 두 줄이 들어오고, 끝에 세로 지움 선이 목록을 비운 뒤 첫 구도로 돌아와 끊김 없이 되풀이된다. 소프트웨어 출시, 기능 한 가지 소개, 생산성 도구의 짧은 홍보에 맞는다.

출처 · c2:graphite-ui. 원래 글은 긴 스타일 명세다(색 다섯 개, 글꼴, 가감속 수치, 움직임 규칙, 대표 동작 네 가지, 구도, 실제 화면 녹화를 넣는 법, 금지 목록). 그러나 장면이 몇 초에 바뀌는지, 창이 화면을 얼마나 차지하는지, 3D 기울기의 크기, 제목의 실제 크기, 바탕의 점 격자, 중간의 알림 카드는 적혀 있지 않다. 이 노트는 영상 프레임을 보고 그 빈자리를 채웠다.
측정 · 파일 1280x720 · 30fps · 12.0초. 크기는 1920x1080 기준으로 바꿔 적는다(1.5배). 장면 감지 컷은 0회다. 모든 변화가 카메라와 화면 요소의 움직임이다. 움직임 세기는 평균 2.3 으로 아주 낮다. 큰 구간은 4.5~5.0초(8.7~9.0, 창이 돌아 비키는 순간), 1.5초(6.9, 기운 창이 평평해지는 순간), 6.5~7.0초(3.7~4.4), 10.5초(3.8, 첫 구도로 돌아가는 순간)다. 2.5초(0.4), 5.5초(0.5), 11.5초(0.1)는 거의 멈춰 있다. 색 값은 프레임에서 잰 근삿값이다.
소리 · 듣지 못했다. 측정값만 적는다. 이 파일에는 소리 트랙이 없다.

## 1. 본질

- 원래 글의 색 다섯 개(바탕, 판, 글자, 흐린 글자, 초록 하나)는 화면과 거의 같다. 되풀이하지 않는다.
- 영상에서 잰 값(근삿값).
  - 바탕 · #0D0E13. 네 모서리는 #0A0B0F~#0B0C11 로 조금 더 어둡다. 아주 약한 비네트가 있다.
  - 창 판 · #16171C. 판 안의 목록 칸 바탕은 #16171C 그대로이고, 칸을 나누는 선만 조금 밝다.
  - 초록 · 단추 가운데 #3DD58C. 원래 글의 값과 같다.
  - 제목 글자 · #EAEBF0.
  - 목록의 뼈대 막대(글자 자리) · #5F6065 근처. 체크된 뒤에는 그 위로 밝은 회색 줄이 그어진다.
- 바탕에 점 격자가 있다. 원래 글에는 없다. 점 간격은 약 41px(720 원본에서 27~28px), 가장 밝은 점이 #292A2F 근처다. 바탕과 밝기 차이가 거의 없어서 압축 영상에서는 잘 안 보인다. 그러나 빈 왼쪽 절반이 완전히 검게 죽지 않게 해 준다.
- 실제 단어는 화면에 최대 3개다. 창 제목 한 낱말, 단추 글자 한 낱말, 큰 제목 두 줄. 나머지 글자 자리는 모두 뼈대 막대다. 원래 글이 정한 실제 단어 수 상한(6개) 안에 든다.
- 초록은 늘 한 곳 이상에 있다. 단추, 커서 누름, 체크 상자, 제목 아래 진행선, 알림 카드의 원. 다른 강조색은 없다.
- 아닌 것 · 유리 효과, 빛 번짐, 보라색 그라데이션, 회전하는 로고, 컷.

크기(1920 기준).

- 기운 넓은 구도(0.0초) · 창이 가로 14~100%(오른쪽은 화면 밖), 세로 17~100% 를 차지한다. 판 색 화소가 화면의 약 53% 다.
- 평평한 가까운 구도(3.0초) · 창이 가로 0~88%, 세로 7~100%. 판 색 화소가 화면의 약 78% 다. 줄 간격 약 127px(화면 높이의 11.8%), 뼈대 막대 높이 약 18px, 체크 상자 약 36px, 단추 약 250x80px(가로의 13%), 창 제목 낱말의 대문자 높이 약 45px(높이의 4.2%).
- 돌아선 구도(5.5초) · 창이 가로 49~100% 에 있다. 판 색 화소가 화면의 약 46% 다. 제목 덩어리는 가로 6.3~40.4%, 세로 35~69%.

## 3. 움직임

- 원래 글의 가감속 수치(착지 0.6초, 카메라 1.2초, 튀지 않음)와 가림막 뒤에서 나오는 글자는 화면과 맞다.
- 영상에서 확인한 점.
  - 처음 목록이 들어올 때는 줄당 약 0.08초 간격이다(0.25초 2줄 → 0.75초 8줄). 원래 글의 목록 들어오기 간격 0.04초보다 느리다.
  - 체크 연쇄는 줄당 약 0.1초다(3.25초 1줄 → 3.75초 6줄). 원래 글의 0.12초와 거의 같다. 이때 제목 아래 진행선이 체크 연쇄와 같은 속도로 자란다. 원래 글에는 진행선이 없다.
  - 카메라 이동은 1.0초 안팎이다. 이동 사이에는 길게 멈춘다. 움직임 세기 평균이 2.3 으로 낮은 이유다. 12초 가운데 약 8초가 0.5~1.5 의 거의 멈춘 화면이다.
  - 카메라가 멈춰 있어도 완전히 서지는 않는다. 5.5~7.5초에 창이 아주 조금씩 더 돌아선다.
- 커서는 한 번만 누른다. 누른 뒤에는 화면에서 거의 움직이지 않는다.

## 4. 전환

- 컷이 없다. 장면 바뀜은 세 가지 방법뿐이다.
  - 카메라 이동 · 기운 넓은 구도 → 평평한 가까운 구도(1.25~2.25초), 평평 → 돌아섬(4.5~5.5초), 빈 창 → 첫 구도(10.25~11.25초).
  - 가림막 · 제목은 아래 가장자리에서 올라와 들어오고(5.0~5.5초), 위 가장자리로 올라가 빠진다(8.5~9.0초). 페이드가 없다.
  - 지움 선 · 9.35~9.7초. 밝은 회색 세로선(두께 약 2px)이 목록을 왼쪽에서 오른쪽으로 0.35초에 지난다. 선의 왼쪽은 체크 전 상태가 아니라 빈 칸이 된다.
- 끝은 첫 프레임과 같은 구도다. 원래 글이 정한 되풀이 고리다. 11.25~12.0초가 0.0초와 거의 같은 화면이다.

## 5. 타이포

- 원래 글의 글꼴 굵기와 자간 규칙은 화면과 맞다. 되풀이하지 않는다.
- 큰 제목 · 두 줄, 왼쪽 정렬. 대문자 높이 약 130px(화면 높이의 12%), 글자 크기로 약 178px(높이의 16.5%), 줄 간격 약 195px(높이의 18%). 왼쪽 끝은 가로 6.3%(원래 글의 왼쪽 여백 120px 와 맞다). 세로 가운데보다 조금 위(35~69%)에 놓인다.
- 창 안의 낱말 · 대문자 높이 약 45px. 단추 글자는 그보다 작다(약 22px).
- 우리 판에서는 한국어 글자가 140px 를 넘지 못한다. 그래서 큰 제목은 원본보다 작아진다(## 7).

## 6. 가져올 것

- 12초 판에서 꼭 남길 대표 장면 · 원본 3.0~3.75초의 "초록 커서가 초록 단추를 한 번 누름 → 단추 글자가 밀려 나가고 체크 → 줄 6개가 위에서부터 0.1초 간격으로 체크되고 그어짐 → 제목 아래 초록 진행선이 같이 자람"이다. 창은 평평하게 가로 0~88% 를 덮고(판 색이 화면의 약 78%), 줄 간격 약 127px, 단추 약 250x80px 다. 한 번 누름에 여러 줄이 연쇄로 끝나는 것이 빠지면 이 영상이 아니다.
- 12초 판 압축 예 · 원본이 이미 12초 되풀이 영상이다. 길이는 그대로 두고 배분만 바꾼다. 0~1.0초 기운 넓은 구도와 줄 들어오기(원본 1.25초), 1.0~2.0초 카메라가 평평해짐, 2.0~2.6초 커서 이동(원본 0.75초), 2.6~4.0초 대표 장면(누름 + 체크 연쇄 0.6초 + 멈춤 0.6초, 원본 멈춤 0.75초), 4.0~5.0초 창이 돌아 비킴과 제목 들어옴, 5.0~8.0초 제목과 창(알림 카드 0.4초 포함, 원본 3.25초), 8.0~8.5초 제목 빠짐, 8.5~9.0초 지움 선, 9.0~10.0초 첫 구도로 복귀, 10.0~12.0초 첫 구도에서 멈춤. 되풀이가 필요 없으면 9.0초 이후의 복귀 3초를 빼고 그 시간에 두 번째 기능(예 · 또 하나의 누름 연쇄)을 넣는다. 빈 창 0.5초(원본 9.75~10.25초)는 뺀다.
- 3D 카메라 세 자세 · 기울어진 넓은 구도 → 평평하고 가까운 구도 → 돌아서서 제목에 자리를 내줌. 원래 글이 정한 순서를 화면도 그대로 따른다.
- 거의 멈춘 화면이 대부분이고, 바뀔 때만 1초 안팎으로 움직인다. 차분한 제품 영상의 박자다.
- 첫 프레임과 마지막 프레임이 같은 구도다.

## 7. 함정

- 화면의 창 제목 낱말, 단추 글자, 큰 제목 두 줄은 원작의 문장이다. 옮기지 않는다. 역할(창 이름 한 낱말, 동작 한 낱말, 결과를 말하는 짧은 제목 두 줄)만 가져온다.
- 큰 제목 크기 · 한국어 140px 규칙 때문에 원본의 178px 를 못 쓴다. Pretendard SemiBold 140px, 자간 -0.03em, 줄 간격 1.1(154px) 두 줄로 둔다. 제목 덩어리 높이는 약 300px(화면 높이의 28%)가 되어 원본(약 360px)보다 작다. 줄인 무게는 창을 더 크게(돌아선 구도에서 가로 45~105%) 두어 메운다. 제목을 한 줄 4~6자로 짧게 쓴다.
- 점 격자를 빼면 왼쪽 절반이 완전한 검정이 된다. 5.5~8.5초 화면의 절반이 비어 보인다. 바탕에 41px 간격, 지름 2px, #26272C 점을 깐다.
- 초록을 단추에만 두면 체크 연쇄 뒤 초록이 갑자기 늘어나는 맛이 안 난다. 체크 상자, 진행선, 알림 카드 원까지 같은 #3DD58C 하나로 쓴다. 다른 초록(밝기만 다른 초록 포함)을 섞지 않는다.
- 3D 기울기 · 원래 글은 첫 구도의 기울기 각도와 화각을 숫자로 정하지 않았다. 너무 약하게 기울이면 평평한 구도와 차이가 안 난다. 0.0초 구도는 창 위쪽 모서리가 오른쪽으로 약 9° 올라가고, 아래쪽이 더 가까워 넓어 보일 만큼 기울인다(## 8 의 값).
- 움직임 세기 · 이 영상은 평균 2.3 으로 일부러 조용하다. 다른 영상 규칙의 "빈 프레임 금지"에 걸려 매 순간 무언가를 움직이면 이 톤이 깨진다. 멈춘 구간에도 카메라를 아주 천천히 흐르게만 한다(초당 0.3° 이하 회전).
- 실제 앱 화면을 넣을 때 · 원래 글처럼 판 안에 넣고 같은 3D 카메라에 붙인다. 화면 녹화가 판보다 밝으면 초록이 가장 밝은 것이 아니게 된다. 녹화의 밝기를 10~15% 낮춘다.
- 커서 누름 고리를 크게 하면 빛 번짐처럼 보인다. 지름 약 60px, 두께 2px, 0.3초에 사라지게 한다.

## 8. 코드로 재현 못 하는 요소와 대체 방법

원본도 코드로 만든 영상이다. 대부분 DOM/CSS 로 된다. 여기서는 우리 seek(t) 방식에서 틀리기 쉬운 요소와 구체 값을 적는다. 값은 1920x1080 기준이다.

| 요소 | 왜 어려운가 | 대체 방법(구체 값) | 대체하면 잃는 것 |
|---|---|---|---|
| 3D 로 기운 앱 창 | 원근과 세 자세 사이의 부드러운 이동을 맞춰야 한다 | DOM 판(폭 1800px, 높이 1150px, 모서리 16px, 테두리 1px #26282E)을 `perspective: 1800px` 무대에 놓는다. 넓은 구도 · `rotateX(38deg) rotateZ(-9deg) translate3d(150px, 120px, -600px)`. 평평 · `rotateX(0) rotateZ(0) translate3d(-160px, 60px, 0)`. 돌아섬 · `rotateY(-28deg) translate3d(820px, 0, -250px)`. 세 값 사이를 seek(t) 에서 직접 보간한다(`cubic-bezier(0.65, 0, 0.35, 1)` 에 해당하는 식, 1.0초). 값은 눈대중이므로 `render.mjs --snap 0,3,5.5` 로 ## 2 의 차지 비율(53%·78%·46%)에 맞춘다 | 없음에 가깝다 |
| 확대된 3D 판의 글자 흐림 | CSS 3D 판을 크게 키우면 글자가 번진다 | 판을 처음부터 최종 크기로 만들고 `scale` 을 1 이하로만 쓴다. 흐리면 three.js 로 바꾼다 · `THREE.PlaneGeometry(18, 11.5)` 에 판 전체를 그린 canvas(3600x2300)를 `THREE.CanvasTexture` 로 입히고 `THREE.PerspectiveCamera` 시야각 35° 로 같은 세 자세를 잡는다. 카메라 이동은 `LOOKS.fly(cam, keys, t)` | canvas 판이면 글자 렌더 검사(`render.mjs` 글꼴 검사)가 DOM 만큼 쉽지 않다 |
| 판 그림자 | 기운 판의 그림자 방향이 자세마다 달라야 한다 | 판 뒤에 같은 변형을 받는 검은 판을 하나 더 두고 `filter: blur(40px)`, 불투명도 0.5, 아래로 40px 어긋나게 한다. three.js 판이면 `LOOKS.floor` 대신 판 바로 뒤 평면에 방사형 그라데이션 canvas 를 입힌다 | 실제 빛 계산의 그림자 |
| 점 격자 바탕 | 없다. CSS 로 된다 | `background: radial-gradient(circle, #26272C 1px, transparent 1.5px) 0 0 / 41px 41px, #0D0E13`. 비네트는 위에 `radial-gradient(ellipse at center, transparent 55%, rgba(0,0,0,.25))` | 없음 |
| 가림막에서 나오는 큰 제목 | 없다. DOM 으로 된다 | 줄마다 `overflow: hidden` 상자(높이 160px)에 넣고 안쪽 글자를 `translateY(100%) → 0` 으로 0.6초, `cubic-bezier(0.16, 1, 0.3, 1)`. 둘째 줄은 0.08초 늦게. 빠질 때는 `0 → -100%`, 0.4초, 첫 줄 먼저 | 없음 |
| 체크 그리기와 줄 긋기 | 없다. SVG 로 된다 | 체크 상자 36px 안의 SVG 체크 경로를 `stroke-dasharray` 길이만큼 두고 `stroke-dashoffset` 을 1 → 0 으로 0.2초. 긋는 선은 뼈대 막대 위의 높이 2px #9A9BA0 막대를 `scaleX(0 → 1)`, 왼쪽 기준, 0.25초. 줄 i 는 3.25 + 0.1·i 초에 시작한다 | 없음 |
| 진행선 | 없다 | 창 제목 아래 높이 4px #3DD58C 막대, 폭 = 창 목록 폭 × (체크된 줄 수 ÷ 전체 줄 수). 줄이 체크될 때마다 0.15초에 늘린다 | 없음 |
| 세로 지움 선 | 없다. CSS 로 된다 | 목록 영역에 `clip-path: inset(0 0 0 X%)` 를 주고 X 를 0 → 100 으로 0.35초. 같은 X 위치에 높이 = 목록 높이, 폭 2px, #C8C9CE 선을 둔다 | 없음 |
| 커서 | 운영체제 커서 그림을 쓰면 안 된다 | SVG 화살표(높이 36px, 채움 #3DD58C, 테두리 1.5px #0D0E13)를 직접 그린다. 누름 순간 0.08초 동안 `scale(0.9)`, 둘레에 지름 60px 고리 | 없음 |
| 글꼴 | 원래 글의 산세리프가 없다 | 한국어는 Pretendard SemiBold(제목)·Regular(창 안), 숫자와 라틴 낱말은 InterVariable 굵기 600, `font-variant-numeric: tabular-nums` | 원래 글꼴의 좁은 자간 인상이 조금 다르다 |
